# Windows 本机打开与停止 Vio

本入口用于当前 Windows 电脑上的个人受控运行。它固定使用本仓库、现有 `backend/data/vio-live.dev.sqlite`、`127.0.0.1:8787` 后端和 `127.0.0.1:5173` 前端；不会访问 Continuity Engine，不会配置或调用 Provider，也不是服务器部署、手机入口或 R7 功能。

## 固定运行版本

- 已验证 Node.js：`22.23.1`；仓库接受范围为 `>=22.23.1 <23.0.0`。
- 固定包管理器：`pnpm 11.9.0`，由根 `package.json` 的 `packageManager` 声明。
- 当前个人数据库：本仓库绝对路径下的 `backend/data/vio-live.dev.sqlite`。首次准备不会创建替代空库，日常启动也不会改用其他 checkout 的数据库。

不要把当前个人数据库、运行状态或构建目录复制到另一份分支后直接启动。外部运行绑定会同时核对仓库和数据库的规范化绝对路径，不一致时 fail closed。

## 只做一次：首次准备

双击仓库根目录的 `首次准备 Vio.cmd`（英文同义入口为 `Prepare Vio.cmd`）。该入口会：

1. 校验 Node 版本、固定的 pnpm 版本和现有个人数据库是否存在；
2. 设置 `COREPACK_ENABLE_NETWORK=0`，只使用本机已缓存的 pnpm `11.9.0`；
3. 严格执行 `pnpm install --offline --frozen-lockfile --force`，只重建本仓库根 `node_modules`，不在线回退、不升级依赖、不改锁文件；
4. 执行 TypeScript 检查和前端生产构建；
5. 把构建指纹写入被 Git 忽略的 `dist/vio-local-build.json`，把仓库/数据库绑定写到 `%LOCALAPPDATA%\VioLive\runtime\local-runtime.json`。

缓存不完整、版本不匹配、锁文件不一致、数据库缺失或端口被占用时，准备会明确失败并停止。它不会启动服务或打开浏览器。更新仓库内前端、后端、迁移或启动脚本后，日常打开会拒绝旧构建；再次执行首次准备即可生成匹配当前 checkout 的构建。

只读预检可在终端运行：

```powershell
.\首次准备 Vio.cmd --plan
```

预检不安装、不构建、不启动服务。

首次准备必须由之后实际双击运行 Vio 的同一个 Windows 桌面用户执行。自动化工具或施工沙箱视图中看似存在的 `%LOCALAPPDATA%` 文件，不能代替普通桌面进程的真实读取验证。运行状态现在也会先严格读取运行配置；配置不存在、当前用户不可读或 JSON 损坏分别返回 `RUNTIME_CONFIG_MISSING`、`RUNTIME_CONFIG_UNREADABLE`、`RUNTIME_CONFIG_INVALID_JSON`，不会再合并成含糊结果。

## 只做一次：初始化个人空间

若首次打开页面显示需要“初始化邀请”，按以下顺序操作：

1. 双击 `停止 Vio.cmd`，确保本入口启动的前后端已经停止；
2. 双击 `初始化个人空间 Vio.cmd`（英文同义入口为 `Initialize Personal Vio.cmd`）；
3. 入口验证 `local-runtime.json` 与当前仓库、现有 `backend/data/vio-live.dev.sqlite` 完全一致，并确认没有运行状态或 5173/8787 监听；
4. 成功后，一次性邀请通常会在记事本中打开，并保存在 `%LOCALAPPDATA%\VioLive\private\personal-initialization-invitation-*.txt`；若记事本未能打开，只按命令返回的 `invitationFile` 本地路径手动打开该文件，再把其中的邀请复制到 Vio 初始化页面；
5. 在页面里由本人设置 12—256 字符的个人访问口令。该口令与邀请不是同一个值；脚本不读取、不生成、不记录口令；
6. 再双击 `打开 Vio.cmd`，在 15 分钟有效期内完成页面初始化。成功后请关闭记事本，并由本人安全删除已经消费的邀请文件。

初始化入口不会创建或替换空数据库，也不会接受另一 checkout、另一数据库或命令行路径。Vio 正在运行、运行状态无法证明已停止、配置/数据库/私有目录不安全时均拒绝；请先按提示停止并核对，不要删除数据库或绕过绑定。重复点击会复用仍有效且可读取的同一邀请文件；若数据库中有未消费邀请但私有文件丢失，或邀请已经过期，入口会在受控事务中使旧资格失效并创建一个新的 `wx` 文件，从而不会留下“数据库只有 hash、本人拿不到邀请”的死状态。已有所有者时不再生成邀请。

通用 `backend/scripts/initialize-personal.js` 仍用于显式的仓库外数据库部署准备，并继续拒绝仓库内数据库。上述双击入口是当前 Windows 本机绑定的专用途径，不会削弱正式 CLI 的安全规则。两种入口都不启动 Engine、Provider 或模型，不读取 API Key，也不会产生费用。

## 日常打开

双击 `打开 Vio.cmd`（英文同义入口为 `Open Vio.cmd`）。入口会：

1. 核对运行绑定、依赖完整性和构建指纹；
2. 只在 loopback 启动 Vio 后端和已准备的静态前端；
3. 等待后端数据库健康检查与前端构建健康检查都通过；
4. 就绪后打开 `http://127.0.0.1:5173/`。

日常打开不会运行 pnpm、安装/升级依赖、构建前端或访问网络。重复双击会通过运行实例状态和命名管道所有权证明复用同一实例，不会再启动一套服务。页面请求保持同源，`/api/*` 和 `/health` 只转发到绑定的本机 Vio 后端；绝对 URL 目标会被拒绝。

## 日常停止

双击 `停止 Vio.cmd`（英文同义入口为 `Stop Vio.cmd`）。停止入口只向本入口创建、且能通过随机实例 ID 与控制令牌证明所有权的运行实例发送停止请求。它不会按进程名或端口强制结束未知进程，也不会删除数据库。

若 5173/8787 被其他程序占用、运行状态文件损坏或所有权无法证明，入口会显示错误并保留现场，不会结束未知进程。此时不要手工删除状态或数据库；先确认占用来源。

## 数据和运行文件

- 个人数据：`backend/data/vio-live.dev.sqlite`，由现有后端正常使用；本轮验证没有用它做破坏性测试。
- 构建结果：仓库根 `dist/`，已被 Git 忽略，可由首次准备重建。
- 运行绑定和所有权状态：`%LOCALAPPDATA%\VioLive\runtime\`。
- 一次性个人初始化邀请：`%LOCALAPPDATA%\VioLive\private\`；文件包含敏感的一次性资格，不应上传、复制到日志或发送到聊天窗口，完成初始化后由本人安全删除。
- 运行日志：`%LOCALAPPDATA%\VioLive\logs\`。

停止和再次打开均保留同一数据库。自动化验收使用系统临时目录中的隔离 SQLite，覆盖并发重复打开、停止、再次打开、端口冲突、错误所有权和数据 canary 保留，没有用现有个人数据库执行破坏性验证。

## 当前边界

- 入口只监听本机 `127.0.0.1`，不是手机、局域网、HTTPS 或云端启动方式。
- 不启动、探测或连接真实 Continuity Engine。
- 不读取环境中的 `VIO_MODEL_API_KEY_*`；运行子进程也不会继承这些值。
- 打开页面、健康检查和状态查询本身不调用模型或 Provider；是否发生个人聊天模型调用仍由既有 R1—R6 业务与安全门控决定。
- 本补修没有开始 R7，没有制作桌面安装包，也没有实现无人值守服务器部署。
