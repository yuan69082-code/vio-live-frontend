# 05｜对话上下文与连续性接口

## 状态

- 文档状态：基础实现已落地，持续维护
- 对话事实存储：Conversation、Message 与 MessageVersion 线性文本基础已实现
- 摘要与跨窗口：ConversationSummary、来源引用和同主体跨窗口最新摘要读取已实现
- 上下文装配与状态回写：只读 Context 投影与显式 `state_update` 持久化已实现
- 连续性接口：需要与独立连续性引擎保持稳定边界
- 当前限制：不生成摘要、不调用模型或连续性引擎，不定义内部算法、提示词渲染、Token 预算或 Memory 检索

当前平台可以保存调用方提交且带来源的会话摘要与主体状态版本，并按固定顺序装配已有事实。所有内容仍由开发调用方提供；上下文装配是只读数据投影，不会自动生成摘要、调用模型、执行状态演化或连接 continuity-engine。基础结构已保存不等于真实连续性已经生效。

## 当前基础实现

- `conversation_summaries`：按用户、主体和 Conversation 保存不可变摘要及会话内单调版本。
- `conversation_summary_sources`：每个摘要至少引用一个同会话 MessageVersion 或同主体 Event；来源和摘要同事务保存。
- `subject_states`：不可变保存 `state_update` 的当前状态、情绪、强度、变化原因、连续性约束和来源。
- `subject_state_unresolved_events`：按顺序保存同主体未解决 Event 引用。
- `subject_state_heads`：只保存每个主体的当前状态指针；切换指针不覆盖历史状态。
- Context Service：读取已有主体设定、当前状态、未解决事件、近期消息和其他窗口最新摘要；不持久化装配结果。
- 当前没有 ConversationSummary 或 SubjectState 自动 Event，避免派生数据在没有消费策略时形成循环。

## 目标

让智能体更换模型或切换对话窗口后，仍能延续身份、关系、当前状态、未完成事项和相关长期记忆，同时避免每轮把全部历史内容交给模型。

## 摘要应覆盖的内容

- 事件重点：发生了什么、未完成任务和已确定决定
- 当前状态：情绪、强度、变化原因和是否持续
- 当前认知：对用户、关系、任务和局势形成的理解
- 想法与感受：判断、担忧、期待、犹豫或联想
- 来源引用：关联窗口、消息、时间、工具结果和记忆来源

## 跨窗口原则

- 按需读取上一窗口摘要、相关原文或完整内容。
- 不在每轮无差别加载全部历史对话。
- 用户可控制本地记忆是否参与上下文。
- 本地记忆应支持加密、容量管理、备份、迁移和删除。
- 启动软件本身不调用模型。

当前跨窗口接口以当前 Conversation 为排除项，只在相同 `user_id + subject_id` 范围内为每个其他 Conversation 返回最新摘要，并限制返回数量。它不扫描或返回其他窗口的完整消息正文；需要原文时必须通过摘要保存的来源引用在后续受控流程中读取。

## 每轮上下文装配顺序

每次未来调用聊天模型前，平台后端按以下顺序准备内容：

1. 系统安全规则
2. AI 助手全局设定
3. 当前主体状态
4. 当前未解决事件
5. 最近若干轮原始对话
6. 相关长期记忆
7. 用户本轮消息

该顺序是产品级约束。当前 Context API 已按此顺序返回结构化 section：系统安全规则只保留 `reserved` 位置，长期记忆固定返回 `not_implemented`，最后一条用户消息从近期消息区移到本轮消息区以避免重复。具体提示词、相关性、长度、Token 预算和模型格式在真实模型接入时再确定。

## 模型返回约定

模型每轮返回两个逻辑部分：

- `reply`：显示给用户的回复
- `state_update`：回复后需要保存的状态变化

`state_update` 初始需要表达：

- 当前情绪
- 情绪强度
- 变化原因
- 是否仍有未解决事件
- 下一轮需要保持的连续性约束

平台后端当前已提供 `state_update` 接收和保存接口，并在后续 Context 装配中重新读取当前状态。输入必须引用同主体 MessageVersion、Event 或 ConversationSummary；未解决 Event 也必须属于同一主体。当前情绪和未解决事件不依赖长对话重新猜测，但本阶段的状态内容由开发调用方显式提交，不代表模型或 continuity-engine 已生成。

## AI 助手全局设定

每个主体拥有长期生效的名字、性格、人设、表达方式、关系定义、长期要求和禁止事项。除非用户明确修改或切换主体，否则这些设定跨窗口保持。

长期设定可以影响表达和行为偏好，但不能绕过：

- 账号与主体隔离
- 工具和设备权限
- 法律要求
- 系统最低安全规则

## 与连续性引擎的接口边界

### 平台后端提供

- 当前用户和主体标识
- 本轮事件、消息和来源引用
- 已授权的记忆范围
- 模型返回的状态更新

当前只实现上述数据的本地保存与只读投影，没有向 continuity-engine 发出请求。Context 响应明确标记 `modelCall`、`externalApiCall`、`continuityEngineCall` 均为 `not_performed`。

### 连续性引擎提供

- 当前主体状态
- 与本轮相关的连续性约束
- 允许读取的记忆或摘要结果
- 状态写入结果

### 不在本目录定义

- 身份、关系、情绪和状态演化的内部算法
- 连续性引擎的学习机制
- 连续性引擎的内部存储结构

## 第一版验收方向

- 同一主体跨窗口保持全局设定和当前状态。当前基础已通过用户/主体复合归属、摘要和状态持久化验证。
- 每轮装配包含明确的安全、状态、事件、对话和记忆层级。当前基础已提供结构顺序，其中规则正文和 Memory 仍明确未实现。
- 模型更换不会导致主体状态丢失。
- 摘要可以追溯到来源。当前基础要求每项摘要至少引用一个经归属验证的 MessageVersion 或 Event。
- 窗口重置不会自动删除连续状态。

真实模型更换与窗口重置仍需后续实现验证，不能由当前只读 Context 投影冒充完成。
