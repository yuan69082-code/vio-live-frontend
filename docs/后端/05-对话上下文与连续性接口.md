# 05｜对话上下文与连续性接口

## 状态

- 文档状态：基础实现已落地，持续维护
- 对话事实存储：Conversation、Message 与 MessageVersion 线性文本基础已实现
- 摘要与跨窗口：ConversationSummary、来源引用和同主体跨窗口最新摘要读取已实现
- 平台事实投影与状态历史：现有只读 Context 投影与显式 `state_update` 持久化已实现；接入后 Context 只能作为平台事实来源，`state_update` 只能改为引擎权威状态投影入口或停用
- AI 助手全局设定：Subject 身份与一对一长期设定、读取/更新 API 及 Context 投影已实现
- AI 私域 Context：独立、受 Permission/Security Policy 保护的私域投影已实现；不会自动并入通用 Context
- 本地记忆 Context：只读取用户明确标记 `participatesInContext=true` 的生活模块记忆，并经 `life_data` 安全链形成独立投影；不会自动并入通用 Context
- 连续性接口：`Continuity Integration Contract v1` 已完成设计，尚未开始实际接入
- 当前限制：不生成摘要、不调用模型或连续性引擎，不定义内部算法、提示词渲染、Token 预算或 Memory 检索

当前平台可以保存调用方提交且带来源的会话摘要与主体状态版本，并按固定顺序投影已有事实。所有内容仍由开发调用方提供；这个只读结果不是最终认知 Context，不会自动生成摘要、调用模型、执行状态演化或连接 continuity-engine。基础结构已保存不等于真实连续性已经生效。

连接后的权威边界已经固定：continuity-engine 是 SubjectState 唯一权威来源；Vio 只保存引擎状态的受控投影、快照、缓存或审计记录。现有开发调用方 `state_update` 能推进 Vio 当前状态指针，是接入前实现而不是目标架构，后续必须收口，不能与引擎同时维护两套状态。

## 当前基础实现

- `conversation_summaries`：按用户、主体和 Conversation 保存不可变摘要及会话内单调版本。
- `conversation_summary_sources`：每个摘要至少引用一个同会话 MessageVersion 或同主体 Event；来源和摘要同事务保存。
- `subject_states`：不可变保存 `state_update` 的当前状态、情绪、强度、变化原因、连续性约束和来源。
- `subject_state_unresolved_events`：按顺序保存同主体未解决 Event 引用。
- `subject_state_heads`：只保存每个主体的当前状态指针；切换指针不覆盖历史状态。
- `assistant_global_settings`：与 Subject 一对一保存人格描述、表达方式、关系定义、长期要求和禁止事项；名称/头像继续由 Subject 唯一保存。
- Context Service：读取已有主体设定、当前状态投影、未解决事件、近期消息和其他窗口最新摘要；不持久化结果，接入后只作为平台事实包来源。
- Assistant Private Context：按用户、助手和 Space 读取已授权的私域当前版本；与通用 Context 分开，不持久化投影结果。
- 当前没有 ConversationSummary 或 SubjectState 自动 Event，避免派生数据在没有消费策略时形成循环。

## 目标

让智能体更换模型或切换对话窗口后，仍能延续身份、关系、当前状态、未完成事项和相关长期记忆，同时避免每轮把全部历史内容交给模型。

## 摘要应覆盖的内容

- 事件重点：发生了什么、未完成任务和已确定决定
- 当前状态：情绪、强度、变化原因和是否持续
- 当前认知：对用户、关系、任务和局势形成的理解
- 想法与感受：判断、担忧、期待、犹豫或联想
- 来源引用：关联窗口、消息、时间、工具结果和记忆来源

## 跨窗口原则

- 按需读取上一窗口摘要、相关原文或完整内容。
- 不在每轮无差别加载全部历史对话。
- 用户可控制本地记忆是否参与上下文。
- 本地记忆应支持加密、容量管理、备份、迁移和删除。
- 启动软件本身不调用模型。

当前跨窗口接口以当前 Conversation 为排除项，只在相同 `user_id + subject_id` 范围内为每个其他 Conversation 返回最新摘要，并限制返回数量。它不扫描或返回其他窗口的完整消息正文；需要原文时必须通过摘要保存的来源引用在后续受控流程中读取。

## 平台事实投影与最终 Context

现有 Context API 按以下顺序返回平台已有事实：

1. 系统安全规则
2. AI 助手全局设定
3. 当前主体状态
4. 当前未解决事件
5. 最近若干轮原始对话
6. 相关长期记忆
7. 用户本轮消息

当前 Context API 已按此顺序返回结构化 section：系统安全规则只保留 `reserved` 位置，长期记忆固定返回 `not_implemented`，最后一条用户消息从近期消息区移到本轮消息区以避免重复。这个顺序是平台事实投影顺序，不再定义最终认知 Context 或最终 prompt。接入后 Vio 负责归属、权限、分类、来源和 Token 门槛，continuity-engine 结合权威状态、引擎 Memory、Wake/Perception 与学习历史组织唯一的最终认知 Context。两边不得各组装一套最终 Context。

AI Private Space 不属于当前通用长期记忆占位。需要私域内容时，调用方必须先通过独立 `private_domain` Permission → Security Policy → Confirmation 接口取得私域 Context 投影，再由后续尚未实现的装配策略决定是否以及如何使用。通用 Context 不能绕过该安全门自动加载私域。

## 引擎结果与状态投影约定

未来一轮连续性处理至少返回两个逻辑部分：

- `reply`：显示给用户的回复
- 权威状态结果：明确“无变化”，或返回带引擎 revision、update ID 和来源的状态投影

权威状态投影至少需要表达：

- 当前情绪
- 情绪强度
- 变化原因
- 是否仍有未解决事件
- 下一轮需要保持的连续性约束

平台后端当前已提供开发调用方 `state_update` 接收和保存接口，并在后续事实投影中重新读取当前状态。输入必须引用同主体 MessageVersion、Event 或 ConversationSummary；未解决 Event 也必须属于同一主体。该接口没有引擎 revision/update ID 或服务身份依据，不能直接作为真实接入写入口。接入后只有 continuity-engine 的 Event → Evolution 结果可以推进权威 SubjectState；Vio 只校验并保存投影。

## AI 助手全局设定

每个主体拥有长期生效的名字、性格、人设、表达方式、关系定义、长期要求和禁止事项。除非用户明确修改或切换主体，否则这些设定跨窗口保持。

当前基础以 `GET` / `PATCH /api/v1/users/:userId/subjects/:subjectId/global-settings` 读取和局部更新完整设定。Subject 中的名称与头像是唯一身份来源；一对一 `assistant_global_settings` 保存其余结构。创建主体时默认设定与 Subject 原子提交，既有主体由迁移回填空白值，不从旧 `basicSettings` 猜测人格含义。实际变化与只含字段名的 `subject_updated` Event 原子提交，不在事件中复制设定正文。

Global Settings 与 SubjectState 必须保持以下边界：

- Global Settings 是用户明确配置、跨窗口长期生效、允许原地更新的身份与行为偏好。
- SubjectState 是根据消息、事件或摘要来源形成的动态状态快照，只追加历史版本。
- 更新名称、表达方式、关系、要求或禁止事项不会创建、覆盖或切换 SubjectState。
- `state_update` 也不得反向改写用户明确设置的长期人格或关系定义。

长期设定可以影响表达和行为偏好，但不能绕过：

- 账号与主体隔离
- 工具和设备权限
- 法律要求
- 系统最低安全规则

## 与连续性引擎的接口边界

### 平台后端提供

- 当前 `userId`、`assistantId`、引擎 `subjectId` 绑定、`conversationId` 和 `requestId`
- 本轮消息、ConversationSummary 与来源引用
- Vio Event 转换后的无状态修改能力 Observation
- 经过 Permission、Security Policy 和需要的 Confirmation 筛选的平台事实包
- 用户 Token 预算决定和受控模型/Tool/MCP/设备调用通道

当前只实现部分数据的本地保存与只读投影，没有助手—引擎主体绑定、平台事实包、Observation 投递、幂等请求或 continuity-engine 客户端。Context 响应明确标记 `modelCall`、`externalApiCall`、`continuityEngineCall` 均为 `not_performed`。

私域 Context 投影同样固定标记模型、外部 API 未调用以及 continuity-engine 未接入；它只返回调用方显式保存且已通过安全检查的内容，不生成认知、偏好或状态。

### 连续性引擎提供

- 唯一权威的当前 SubjectState、revision 和可审计演化结果
- Wake、Perception、Thinking、Learning、Action 与 Revision 结果
- 最终认知 Context 的组织和对平台事实/摘要/记忆的采用判断
- 回复结果、消费 Observation 回执，以及需要 Vio 安全执行的能力调用意图

### 不在本目录定义

- 身份、关系、情绪和状态演化的内部算法
- 连续性引擎的学习机制
- 连续性引擎的内部存储结构

正式输入输出、服务端点、鉴权、幂等、失败恢复和状态投影规则见 [14-continuity-engine连接契约v1.md](14-continuity-engine连接契约v1.md)。其中“拟新增”和“待引擎确认”均不是已实现接口。

## 第一版验收方向

- 同一主体跨窗口保持全局设定和当前状态。当前基础已通过用户/主体复合归属、全局设定、摘要和状态持久化验证。
- 每轮装配包含明确的安全、状态、事件、对话和记忆层级。当前基础已提供结构顺序，其中规则正文和 Memory 仍明确未实现。
- 模型更换不会导致主体状态丢失。
- 摘要可以追溯到来源。当前基础要求每项摘要至少引用一个经归属验证的 MessageVersion 或 Event。
- 窗口重置不会自动删除连续状态。

真实模型更换与窗口重置仍需后续实现验证，不能由当前只读 Context 投影冒充完成。
