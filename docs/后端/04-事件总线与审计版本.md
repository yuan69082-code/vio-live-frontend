# 04｜事件总线与审计版本

## 状态

- 文档状态：基础事件系统、对话版本、权限/确认生命周期、安全审计、设备、AI 私域和生活管理最小事件联动已实现；事件消费和生产审计治理仍在规划
- 软件事件系统：已完成 SQLite 记录、用户范围查询和基础 HTTP 接口；事件消费未完成
- 对话版本：已完成线性文本消息的原始、编辑和主体回复重生成记录；删除、分支和重置未完成
- 当前限制：未建立消息队列、中间件、订阅者、投递、重试或连续性引擎连接；摘要和 SubjectState 基础不会自动消费或产生 Event

## 软件事件总线目标

Vio Live 中的重要动作先转换为统一的软件事件。AI 不需要持续扫描全部页面，也能在用户交流、主动唤醒或相关任务发生时知道平台内出现了什么变化。

## 当前基础事件类型

| 事件名 | 范围 | 可进入事件数据的内容 |
| --- | --- | --- |
| `appearance_changed` | 头像、主题等外观变化 | 变化内容、发生时间和最小来源信息 |
| `subject_updated` | AI 主体名字、头像引用或基础设定变化 | 变更字段摘要和关联主体 |
| `permission_created` | 权限规则创建 | 权限 ID、主体、资源、操作、状态和创建原因 |
| `permission_changed` | 权限规则修改或单次消费 | 权限 ID、范围、前后状态和变化原因 |
| `permission_revoked` | 权限规则撤销 | 权限 ID、范围、撤销前后状态和原因 |
| `confirmation_required` | 安全检查要求具体确认 | Confirmation、操作、资源、风险、模式和可选策略 ID；不含执行正文 |
| `life_record_created` | 新增生活记录 | 记录类别、最小结构化摘要和可选关联主体 |
| `life_event_created` | 生活管理记录创建或变化 | 模块、记录 ID 和变化类型；不含生活敏感字段 |
| `budget_changed` | 预算变化 | 模块、预算 ID 和变化类型；不含金额、分类或提醒阈值 |
| `health_record_updated` | 身体指标或目标变化 | 模块、记录 ID 和变化类型；不含身体数值或建议正文 |
| `device_changed` | 设备变化 | 平台设备注册、注册状态、主体授权或操作请求的最小摘要；明确标记未连接、未执行 |
| `conversation_created` | 创建对话容器 | 对话 ID、状态和所属主体；不复制标题 |
| `message_created` | 创建逻辑消息与初始版本 | 对话、消息、版本 ID 和发送者类型；不复制正文 |
| `message_updated` | 用户消息追加编辑版本 | 消息、版本、父版本和版本号；不复制正文 |
| `message_regenerated` | 主体消息追加重生成记录 | 消息、版本、父版本和版本号；不复制正文，也不调用模型 |
| `private_space_created` | 创建 AI Private Space | Space、助手、状态和存储范围；不含正文 |
| `private_memory_updated` | 私域认知、长期偏好、工作或笔记版本变化 | Content/Version、类型、版本和变化原因；不含正文 |
| `private_state_changed` | 私域 AI 状态版本或 Space 状态变化 | Space/Content/Version 与状态变化；不含正文 |
| `wake_configuration_changed` | Wake 规则创建、授权或状态变化 | Wake ID、类型、应用内授权、状态；不含音频 |
| `wake_trigger_prepared` | Wake 触发安全准备 | Wake ID、类型、安全结果和未执行标记 |
| `proactive_prompt_prepared` | 主动提示准备或抑制 | Rule/Record/Event ID、优先级和未投递结果 |
| `token_budget_changed` | Token Budget 创建或更新 | Budget ID、策略、状态和未调用标记 |
| `token_usage_recorded` | 显式 Token 计量写入 | Usage/Budget ID、总量、来源与未计费标记 |
| `background_policy_changed` | 助手后台策略变化 | Policy ID、idle/active、开关与未执行标记 |

能力变化、数据导入/删除/恢复等仍属于产品规划中的事件范围，但本阶段没有新增 `capability_changed` 或 `data_changed` 等可写入类型，也没有开发对应业务模块。新增事件名需要同步更新数据库约束、服务常量、接口契约、测试和版本记录。

Permission 模块按生命周期生成事件：规则创建使用 `permission_created`，实际更新与 `allow_once` 消费使用 `permission_changed`，软删除使用 `permission_revoked`。事件保存最小权限范围与前后状态，并与权限写入同事务提交。Security 在首次创建具体确认时同事务生成 `confirmation_required`；它只表示用户需要决定，不代表真实工具、设备或外部能力已经执行。

`device_changed` 已由 Device 模块用于 `connection_registered`、`registry_status_changed`、`authorization_changed` 和 `operation_requested` 四类平台变化。这里的“连接注册”只表示平台注册了设备元数据，所有事件均保留 `connectionStatus=not_connected`；操作请求保留 `executionStatus=not_executed`，不复制外部设备 ID、位置、凭据、实际操作参数或设备状态。设备、事件和相关操作日志在同一事务提交。

AI Private Space 创建使用 `private_space_created`；AI 状态内容使用 `private_state_changed`；其他四类私域内容使用 `private_memory_updated`。Space/Content 版本与 Event 在同一事务提交，Event 仅携带不透明 ID、类型、版本和变化标识。正文不会进入 Event。

生活管理写入使用 `life_event_created`、`budget_changed`、`health_record_updated`；既有 `life_record_created` 继续作为兼容事件名，但新生活服务不使用。财务/月历/本地记忆创建或标记变化进入 `life_event_created`，预算和身体数据使用专用事件。事件只保存模块、记录 ID 和变化类型，不保存金额、分类、身体数值、月历类型/标题、亲密内容、备注、记忆或建议正文；数据库写入与 Event 同事务提交。

ConversationSummary 可以引用同主体 Event，SubjectState 可以把同主体 Event 标记为未解决来源；这些引用不改变 Event 状态，也不会自动触发模型、连续性引擎或新的派生 Event。摘要和状态当前由开发调用方提交，平台不把派生记录重新写成 Event，以免在没有消费策略时形成循环。

AI Assistant Global Settings 实际变化沿用 `subject_updated`，只记录 `changedFields` 和主体引用，不复制人格、关系、长期要求或禁止事项正文。Subject 身份字段、扩展设定和 Event 在同一事务提交；无变化请求不重复产生事件。该 Event 不会自动生成或修改 SubjectState。

## 当前记录与查询能力

- 每个事件保存 `event_id`、`user_id`、可选 `subject_id`、`event_type`、来源、发生/记录时间、结构化事件数据、摘要和状态。
- 创建事件前校验用户；存在主体时同时校验主体属于该用户。
- 支持按用户查询，并可组合主体、事件类型、状态、发生时间起止范围和数量限制。
- 提供单项查询，事件 ID 始终在用户范围内解析，避免跨用户读取。
- 当前事件为不可原地改写的记录；创建后默认状态为 `pending`，本阶段不提供状态更新或删除接口。
- 当前 SQLite 表和查询索引是开发环境实现，正式事件基础设施仍待后续 ADR。

## 事件安全边界

- API Key、付款密码、完整证件号码等秘密原文不进入事件视图。
- 创建接口会拒绝事件数据中明显的密钥、密码、验证码、Token、Secret 和证件号字段；这只是事件输入安全边界，不是权限系统。
- 事件只携带完成当前判断所需的最小摘要。
- AI 可以选择沉默、调整行为或询问原因，但不能因事件自动获得新权限。
- 普通页面操作只产生事件；只有需要理解或回应时才调用模型。

## 对话版本记录

当前已实现独立 `Conversation`、稳定 `Message` 和不可变 `MessageVersion`。三层均保存用户、主体与会话归属；Message 使用单调 `sequence_number` 表示线性时间线位置，以 `current_version_id` 选择普通消息流正文。每次写入与会话活动时间、最小 Event 同事务提交。

### 用户消息编辑

已实现。编辑只允许 `senderType=user`，请求必须携带当前 `baseVersionId`。后端追加 `edited` 版本并保留原版本；普通消息列表只返回当前版本，版本接口返回完整父链。陈旧 `baseVersionId` 返回冲突。

### AI 回复重生成

已实现数据记录基础。重生成只允许 `senderType=subject`，调用方显式提交新正文和当前 `baseVersionId`；后端追加 `regenerated` 版本。当前不调用模型、不保存 Provider/上下文版本，也不能把该操作宣称为真实 AI 生成。

### 消息删除

仍未实现。未来需保存符合保留规则的受控标记、删除时间和数据状态；不得直接覆盖或物理抹除当前历史。

### 分支与回退

仍未实现。当前只有单一线性时间线和同消息父版本链；不能把 `parent_version_id` 或单个当前指针宣称为分支系统。复杂多用户协作分支继续暂缓。

### 窗口重置

仍未实现。未来保存独立的重置范围和时间；重置只改变当前可见窗口，不自动删除消息历史、主体状态或长期记忆。

## 审计范围

当前已建立独立 `AuditLog` 基础。它不是 Event：Event 表达平台内已经发生的软件变化，AuditLog 表达安全检查、确认及 Permission/APIProvider/Security Policy 配置变化的治理事实。AuditLog 不作为普通软件事件投递，也不会自动进入未来 AI 上下文。

当前审计记录只追加请求范围所属用户、可选主体、操作类型、资源类型/ID、动作、风险等级、Permission 结果、确认模式、结果、固定脱敏原因码、可选确认引用和时间，没有 payload 或正文列。按契约不得把 API Key、身份/支付原文或 AI 私域正文塞入资源引用；当前只启发式拦截常见凭据形态，不构成完整 DLP。当前 `user_id` 是路径限定的查询归属，不是已验证的登录身份；认证接入前路由不得公开。接口不允许客户端创建、修改或删除审计。

已接入的基础范围包括 Permission 创建/更新/删除/单次消费、Security Policy 与用户偏好变更、APIProvider 创建/状态更新、AI 私域访问安全检查结果和确认决定。以下完整范围仍是后续目标：

- 权限申请、授权、拒绝和撤销
- 模型、MCP、Tool 与设备调用
- 高风险操作确认与立即停止
- AI 私域披露申请、开放范围和独立访问历史（当前只有通用最小 AuditLog）
- 数据导入、导出、备份、恢复和删除
- 管理者查看用户、状态、事件、错误和使用日志的行为

## 用户权利与保留

- 隐藏版本不能成为永久不可见黑箱。
- 用户可在数据管理和导出时选择查看、删除或排除隐藏版本。
- 所有审计与隐藏记录仍受保留周期、删除规则和隐私政策约束。
- 具体保留时间和审计可见范围等待后续安全与法律审查决定。
