# 04｜事件总线与审计版本

## 状态

- 文档状态：基础事件系统、对话版本和安全审计基础已实现；事件消费和生产审计治理仍在规划
- 软件事件系统：已完成 SQLite 记录、用户范围查询和基础 HTTP 接口；事件消费未完成
- 对话版本：已完成线性文本消息的原始、编辑和主体回复重生成记录；删除、分支和重置未完成
- 当前限制：未建立消息队列、中间件、订阅者、投递、重试或连续性引擎连接；摘要和 SubjectState 基础不会自动消费或产生 Event

## 软件事件总线目标

Vio Live 中的重要动作先转换为统一的软件事件。AI 不需要持续扫描全部页面，也能在用户交流、主动唤醒或相关任务发生时知道平台内出现了什么变化。

## 当前基础事件类型

| 事件名 | 范围 | 可进入事件数据的内容 |
| --- | --- | --- |
| `appearance_changed` | 头像、主题等外观变化 | 变化内容、发生时间和最小来源信息 |
| `subject_updated` | AI 主体名字、头像引用或基础设定变化 | 变更字段摘要和关联主体 |
| `permission_changed` | 权限变化 | 权限范围、状态和变化原因；当前只实现平台规则，不执行真实资源 |
| `life_record_created` | 新增生活记录 | 记录类别、最小结构化摘要和可选关联主体 |
| `device_changed` | 设备变化 | 设备状态或授权变化摘要；当前不实现设备业务 |
| `conversation_created` | 创建对话容器 | 对话 ID、状态和所属主体；不复制标题 |
| `message_created` | 创建逻辑消息与初始版本 | 对话、消息、版本 ID 和发送者类型；不复制正文 |
| `message_updated` | 用户消息追加编辑版本 | 消息、版本、父版本和版本号；不复制正文 |
| `message_regenerated` | 主体消息追加重生成记录 | 消息、版本、父版本和版本号；不复制正文，也不调用模型 |

能力变化、数据导入/删除/恢复等仍属于产品规划中的事件范围，但本阶段没有新增 `capability_changed` 或 `data_changed` 等可写入类型，也没有开发对应业务模块。新增事件名需要同步更新数据库约束、服务常量、接口契约、测试和版本记录。

`permission_changed` 已由 Permission 模块实际使用：规则创建、实际更新、软删除和 `allow_once` 消费会记录最小权限范围与前后状态，并与权限写入同事务提交。事件仍不代表真实工具、设备或外部能力已经执行。

ConversationSummary 可以引用同主体 Event，SubjectState 可以把同主体 Event 标记为未解决来源；这些引用不改变 Event 状态，也不会自动触发模型、连续性引擎或新的派生 Event。摘要和状态当前由开发调用方提交，平台不把派生记录重新写成 Event，以免在没有消费策略时形成循环。

## 当前记录与查询能力

- 每个事件保存 `event_id`、`user_id`、可选 `subject_id`、`event_type`、来源、发生/记录时间、结构化事件数据、摘要和状态。
- 创建事件前校验用户；存在主体时同时校验主体属于该用户。
- 支持按用户查询，并可组合主体、事件类型、状态、发生时间起止范围和数量限制。
- 提供单项查询，事件 ID 始终在用户范围内解析，避免跨用户读取。
- 当前事件为不可原地改写的记录；创建后默认状态为 `pending`，本阶段不提供状态更新或删除接口。
- 当前 SQLite 表和查询索引是开发环境实现，正式事件基础设施仍待后续 ADR。

## 事件安全边界

- API Key、付款密码、完整证件号码等秘密原文不进入事件视图。
- 创建接口会拒绝事件数据中明显的密钥、密码、验证码、Token、Secret 和证件号字段；这只是事件输入安全边界，不是权限系统。
- 事件只携带完成当前判断所需的最小摘要。
- AI 可以选择沉默、调整行为或询问原因，但不能因事件自动获得新权限。
- 普通页面操作只产生事件；只有需要理解或回应时才调用模型。

## 对话版本记录

当前已实现独立 `Conversation`、稳定 `Message` 和不可变 `MessageVersion`。三层均保存用户、主体与会话归属；Message 使用单调 `sequence_number` 表示线性时间线位置，以 `current_version_id` 选择普通消息流正文。每次写入与会话活动时间、最小 Event 同事务提交。

### 用户消息编辑

已实现。编辑只允许 `senderType=user`，请求必须携带当前 `baseVersionId`。后端追加 `edited` 版本并保留原版本；普通消息列表只返回当前版本，版本接口返回完整父链。陈旧 `baseVersionId` 返回冲突。

### AI 回复重生成

已实现数据记录基础。重生成只允许 `senderType=subject`，调用方显式提交新正文和当前 `baseVersionId`；后端追加 `regenerated` 版本。当前不调用模型、不保存 Provider/上下文版本，也不能把该操作宣称为真实 AI 生成。

### 消息删除

仍未实现。未来需保存符合保留规则的受控标记、删除时间和数据状态；不得直接覆盖或物理抹除当前历史。

### 分支与回退

仍未实现。当前只有单一线性时间线和同消息父版本链；不能把 `parent_version_id` 或单个当前指针宣称为分支系统。复杂多用户协作分支继续暂缓。

### 窗口重置

仍未实现。未来保存独立的重置范围和时间；重置只改变当前可见窗口，不自动删除消息历史、主体状态或长期记忆。

## 审计范围

当前已建立独立 `AuditLog` 基础。它不是 Event：Event 表达平台内已经发生的软件变化，AuditLog 表达安全检查、确认及 Permission/APIProvider 配置变化的治理事实。AuditLog 不作为普通软件事件投递，也不会自动进入未来 AI 上下文。

当前审计记录只追加请求范围所属用户、可选主体、操作类型、资源类型/ID、动作、风险等级、Permission 结果、确认模式、结果、固定脱敏原因码、可选确认引用和时间，没有 payload 或正文列。按契约不得把 API Key、身份/支付原文或 AI 私域正文塞入资源引用；当前只启发式拦截常见凭据形态，不构成完整 DLP。当前 `user_id` 是路径限定的查询归属，不是已验证的登录身份；认证接入前路由不得公开。接口不允许客户端创建、修改或删除审计。

已接入的基础范围包括 Permission 创建/更新/删除/单次消费、APIProvider 创建/状态更新、安全检查结果和确认决定。以下完整范围仍是后续目标：

- 权限申请、授权、拒绝和撤销
- 模型、MCP、Tool 与设备调用
- 高风险操作确认与立即停止
- AI 私域申请、开放范围和访问记录
- 数据导入、导出、备份、恢复和删除
- 管理者查看用户、状态、事件、错误和使用日志的行为

## 用户权利与保留

- 隐藏版本不能成为永久不可见黑箱。
- 用户可在数据管理和导出时选择查看、删除或排除隐藏版本。
- 所有审计与隐藏记录仍受保留周期、删除规则和隐私政策约束。
- 具体保留时间和审计可见范围等待后续安全与法律审查决定。
