# 09｜AI 私域后端规则

## 状态

- 文档状态：数据基础已落地，持续维护
- 实现状态：AI Private Space、五类内容、不可变版本、安全访问、私域 Event、独立 Context 投影和导出清单预留已实现
- 连续性引擎状态：未连接；不生成或维护私域内容
- 当前限制：不实现真实 AI 开放判断、意识、自主行为、机器人连接、删除或真实文件导出

当前实现只保存开发调用方显式提交的数据。字段名中的“AI 状态”“认知”或“私有”不表示平台已经实现意识、内部思维读取、自动形成观点或自主行动。

## 产品定位

AI 私域用于保存智能体暂未主动公开的高敏感主体数据。正文可默认受限，但用户的数据权利与内容披露规则必须分开：未来披露决策不能取消用户依法享有的导出、删除和停用权。

当前基础先建立独立存储、版本、归属和安全门，不实现“由 AI 决定是否公开”的产品流程。

## 当前数据结构

### AI Private Space

每个用户与助手最多一个 Space：

- `space_id`：平台生成的不透明标识
- `user_id`：所属用户
- `assistant_id`：当前映射已有 `Subject.subject_id`
- `status`：`active` 或 `inactive`
- `created_at` / `updated_at`：平台记录时间

Space 与普通用户数据使用独立表。创建空 Space 不接收、读取或返回正文，只用于先取得精确 Permission 的 `resourceId`。

`inactive` 会冻结正文读取、写入、版本历史与 Context 投影；元数据读取、重新启用及保障用户数据权利所需的导出清单仍需经过各自安全链后可用。

### 私域内容版本

当前支持：

| 类型 | 作用 | Event |
| --- | --- | --- |
| `ai_state_record` | 保存调用方提交的 AI 状态记录 | `private_state_changed` |
| `ai_cognition_record` | 保存调用方提交的认知记录 | `private_memory_updated` |
| `ai_long_term_preference` | 保存调用方提交的长期偏好 | `private_memory_updated` |
| `ai_work_record` | 保存调用方提交的工作记录 | `private_memory_updated` |
| `ai_private_note` | 保存调用方提交的私有笔记 | `private_memory_updated` |

每项内容有稳定 `content_id`，每次更新创建新的 `content_version_id`、递增 `version_number` 并引用 `parent_version_id`。调用方必须提交当前 `baseVersionId`；数据库触发器禁止直接更新或删除历史版本。`source_type` 当前固定为 `explicit_api_input`。

## 数据隔离

```text
User Space
  users / conversations / messages / settings / other user data

Assistant Private Space
  assistant_private_spaces
    └─ assistant_private_content_versions
```

- 私域每次查询同时限定 `user_id + assistant_id + space_id`。
- 其他用户、其他助手或错误 Space 组合按未找到处理，不返回内容存在性。
- 通用 Conversation Context 不自动读取私域。
- Event、AuditLog 和 Export Manifest 不复制私域正文。
- 当前开发 SQLite 没有生产级加密，不得公开部署或写入真实凭据、身份秘密和支付秘密。

## 权限与安全

空 Space 创建是无正文的引导步骤。其后固定使用：

| 操作 | Permission action |
| --- | --- |
| 读取 Space、正文、版本和 Context 投影 | `read` |
| 创建或更新内容 | `write` |
| 修改 Space 状态 | `manage` |
| 创建导出清单 | `export` |

所有资源类型固定为 `private_domain`、资源 ID 固定为 `space_id`，流程为：

```text
Permission Check
  ↓
Security Policy Check
  ↓
high-risk Confirmation
  ↓
本地数据操作或拒绝
```

Security 仍返回 `executionStatus=not_executed`，表示没有模型、设备、机器人或外部副作用；用户批准后只执行本地数据库读写。Permission 或 Policy 拒绝时，`result=null`，不得读取或修改正文。

## 私域事件

- `private_space_created`：创建空 Space。
- `private_memory_updated`：创建或更新认知、长期偏好、工作记录或私有笔记。
- `private_state_changed`：创建/更新 AI 状态记录，或修改 Space 状态。

事件只保存 Space、Content、Version、类型、版本和变化标识，不保存正文、凭据或秘密字段。确认请求继续使用现有 `confirmation_required`，最终安全结果进入最小 AuditLog。

## Context 集成边界

私域 Context 使用独立受控接口，只有通过 `read` Permission 与 Security Policy 后才返回指定类型、指定数量的当前版本。响应明确：

- `storageScope=assistant_private_space`
- `userSpaceIncluded=false`
- 模型和外部 API 未调用
- continuity-engine 未调用

该接口只提供未来装配所需的数据投影，不生成 prompt、不计算相关性、不做 Token 预算，也不改变 SubjectState 或 Assistant Global Settings。

## 导出结构预留

当前 Export Manifest 可表达：

- 用户、助手和 Space 范围
- 内容数量、版本数量
- 内容类型、版本号、父版本、来源类型和创建时间
- 未来 `json` 与 `human_readable` 格式
- 是否包含版本历史

当前固定 `exportStatus=not_generated`、`contentIncluded=false`，不创建文件、不返回正文、不传输数据。真实导出必须另行确定认证、重新确认、加密、流式传输、保留、撤销和审计规则。

## 后续披露流程（未实现）

产品规划仍保留模糊目录、查看申请、全部开放、部分开放、暂时拒绝和延后开放。当前数据库/API 没有实现这些状态，也没有让后端或 AI 代替用户/主体作披露决定。

未来实现前必须单独定义：

- 目录最小可见字段和防推断规则
- 开放结果来源、有效期和重复申请
- 部分开放的字段级裁剪
- 用户删除、停用与依法保留
- 真实 AI/continuity-engine 写入与披露决策的授权、可解释性和安全测试

## 第一版基础验收

- User Space 与 Assistant Private Space 独立存储。
- 五类显式输入能够创建、读取、更新并保留不可变历史。
- 读取与修改经过 Permission → Security Policy → Confirmation。
- 跨用户、助手和 Space 访问被拒绝。
- Event、AuditLog 和导出清单不泄露正文。
- 私域可提供独立、受控的 Context 投影。
- 当前阶段不调用模型、continuity-engine、外部 API、机器人或设备。
