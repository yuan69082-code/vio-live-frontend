# 06｜模型路由、密钥与 Token 管理

## 状态

- 文档状态：初始规划
- 真实模型连接：未完成
- Thinking Provider、预算、Wake 和 Resource 仅有规划所述框架状态，尚未形成平台闭环
- 当前限制：不指定具体模型 SDK、计费实现或密钥服务产品

## 目标

允许不同主体和不同任务使用不同模型或服务，同时保持主体状态独立、密钥安全、费用可见，并避免无意义的后台调用和无限 Token 消耗。

## 支持的服务来源

- 官方 API
- 明确标记的第三方中转服务
- 用户自建服务
- 本地模型

中转服务必须说明数据可能经过第三方服务器，不能伪装为官方服务。

## 任务路由范围

| 任务类型 | 初始可配置内容 |
| --- | --- |
| 聊天与长文本 | 默认模型、备用模型、上下文、温度和费用限制 |
| 看图与生图 | 图片理解或生成服务、尺寸、质量和风格 |
| 视频理解与生成 | 上传、抽帧、时长、质量和成本 |
| 语音识别与合成 | 识别服务、声音、语速和情绪 |
| 联网搜索 | 搜索服务、引用规则和隐私要求 |

## 模型服务配置

每项模型/API 配置至少需要表达：

- 显示名称
- 服务商和服务来源
- Base URL
- 模型名
- 接口格式
- 连接测试状态
- 默认任务和适用范围
- 费用说明
- 备用模型

本文件不确定具体字段类型、接口路径或供应商专属参数。

## 路由原则

- 用户可以手动选择模型。
- 后续允许系统按任务选择模型，但第一版不要求完整自动费用优化。
- 主模型不可用时，可按已配置规则使用备用模型。
- 更换模型不改变 `subject_id`、主体状态、长期设定或记忆归属。
- 建议模型和实际调用分开，调用仍受权限与费用限制。

## 密钥管理

- API Key 只能进入服务器密钥库或设备安全存储。
- 密钥不得写入 GitHub、普通日志、事件正文或模型上下文。
- 前端只能看到脱敏状态，不应取回密钥原文。
- 外部服务撤销后，相关密钥和调用能力必须失效。
- 具体加密、轮换和密钥库方案等待安全 ADR 决定。

## Token 与资源原则

- 打开软件不调用模型。
- 普通页面操作优先形成软件事件。
- 只有需要理解、回应或主动唤醒时才调用模型。
- 模型优先读取当前摘要、近期事件和相关记忆。
- 其他内容按需检索，避免上下文无限增长。
- 实际 Token 统计和费用展示在真实模型接入后实现。

## 语音与主动唤醒边界

- 网页/PWA 第一版只支持按钮和前台语音。
- 桌面、锁屏和后台唤醒属于原生 App 或设备伴侣服务。
- 咳嗽、呼救声或自定义声音优先在本机判断，只提交必要事件。
- 触发后可以先询问用户是否需要帮助，不默认直接执行操作。

## 第一版验收方向

- 至少一个真实模型可被手动选择和安全调用。
- 密钥不会出现在前端、日志、事件或 Git 仓库中。
- 上下文装配与 Token 使用范围可解释。
- 模型切换不影响主体连续状态。
- 打开应用和普通浏览不会自动消耗模型 Token。
