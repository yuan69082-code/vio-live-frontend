# Vio Live 数据库设计

## 状态与范围

- 当前阶段：逻辑设计已作为平台后端实现基线
- 设计层级：数据库产品无关的逻辑模型
- 实现状态：账号/User Space/主体、当前助手、统一数据隔离检查、全局设定/私域、对话/摘要/状态、Event、模型/扩展/设备、生活管理、Permission/Security/Confirmation/AuditLog 基础子集已映射到开发期 SQLite；Context 为只读投影，SensitiveData 仅实现分类元数据
- 当前限制：完整通用 Memory、生活记录删除/真实导出、私域披露/删除/真实导出、正式数据库、生产迁移、模型调用和 continuity-engine 未实现

本文说明未来需要保存什么、数据属于谁、对象之间如何关联，以及数据如何版本化、隔离、导出和删除。文中的对象名和字段名是逻辑契约，不等于最终物理表名。

### 当前物理实现子集

- `schema_migrations`：记录已执行的开发数据库迁移。
- `users`：保存用户唯一 ID、邮箱、显示名称、基础状态和时间。
- `user_spaces`：按用户一对一保存空间 ID、开发期未认证身份模式、空间状态和可空当前助手复合外键。
- `subjects`：保存主体唯一 ID、所属用户、名称、头像引用、基础设定、状态和时间。
- `assistant_global_settings`：与 Subject 一对一保存人格描述、表达方式、关系定义、长期要求、禁止事项和时间。
- `assistant_private_spaces`：按用户与助手一对一保存独立私域容器、状态和时间。
- `assistant_private_content_versions`：保存五类私域内容的不可变 JSON 版本、父版本、显式输入来源和时间。
- `conversations`：保存用户/主体双重归属、标题、状态、最近活动和时间。
- `messages`：保存会话内稳定消息 ID、发送者、状态、单调顺序和当前版本指针，不重复保存正文。
- `message_versions`：保存不可覆盖的文本正文、版本号、变化原因和同消息父版本关系。
- `conversation_summaries`：保存会话内单调、不可变的摘要版本和时间。
- `conversation_summary_sources`：保存摘要对同会话 MessageVersion 或同主体 Event 的有序来源引用。
- `subject_states`：保存不可变 `state_update`、主体内单调版本、情绪、强度、变化原因、约束和来源。
- `subject_state_heads`：保存每个用户/主体组合的当前 SubjectState 指针。
- `subject_state_unresolved_events`：保存状态版本引用的同主体未解决 Event。
- `events`：保存用户范围内的十八类软件事件，可选绑定所属主体，并支持按归属、类型、状态和发生时间查询。
- `api_providers`：保存用户所属 Provider 的显示名称、类型、Base URL、接口格式、启停状态、测试状态和空的 Key 安全引用占位。
- `models`：保存用户与 Provider 双重归属、模型名称、模型类型、费用说明、测试状态和创建时间。
- `model_capabilities`：保存 Model 的 `chat`、`long_text`、`vision`、`image`、`video`、`audio`、`search`、`embedding` 能力标签。
- `model_routing_rules`：按用户与六类任务唯一保存默认 Model、可选备用 Model、启停状态和时间。
- `tool_registry` / `mcp_registry` / `skill_registry` / `plugin_registry`：保存用户范围的扩展能力注册元数据，不代表真实连接、安装或执行。
- `tool_usage_records`：保存主体范围的 Tool 安全准备与固定未执行结果。
- `device_registry`：保存用户范围的设备类型、品牌、名称、平台注册状态、未来 Adapter 类型和时间，不保存外部设备 ID、凭据、位置或实际状态。
- `device_capabilities`：保存设备声明的查看状态、开关、调节参数或获取数据能力。
- `device_operation_logs`：保存主体设备操作的权限、安全、确认、审计和事件引用；执行状态固定为 `not_executed`。
- `life_financial_records`：保存主体范围的收入/支出、分类、整数最小货币单位、币种、时间和备注。
- `life_budgets`：按主体、月份和分类唯一保存预算金额及提醒规则。
- `life_calendar_entries`：保存四类月历记录、时间、备注和提醒规则。
- `life_body_records` / `life_body_goals`：保存身体指标历史和当前目标；AI 建议仅为显式输入字段。
- `local_memories`：保存 User Space 本地记忆正文、上下文参与和导出标记，不等同于完整通用 Memory。
- `permissions`：保存用户/主体范围的资源操作权限、五档等级、生命周期状态和时间。
- `security_policies`：按用户、资源类型、动作和风险保存五种精确安全规则。
- `user_security_preferences`：按用户一对一保存默认风险、高风险策略、自动确认范围和禁止范围。
- `security_policy_session_grants`：保存明确确认后形成的精确、30 分钟开发期策略授权。
- `security_confirmations`：保存具体安全请求的作用域、Permission/Policy 快照、开发期安全会话、原因、风险说明、用户选择和单次状态。
- `audit_logs`：只追加安全操作、资源引用、风险、结果、可选确认引用和时间，不保存任意正文。
- 当前物理实现位于 `backend/migrations/` 和 `backend/src/integrations/database/`，只服务于开发闭环。
- 其他逻辑对象仍不得被视为已经存在于数据库中。

## 数据分类

同一对象可以同时带有多个分类，表示不同字段承担不同职责。

| 标记 | 含义 | 典型内容 |
| --- | --- | --- |
| 用户数据 | 能识别用户、由用户输入或直接描述用户的数据 | 账号资料、登录身份、用户消息、用户授权 |
| AI 主体数据 | 归属于特定 `subject_id`、用于保持智能体连续性的内容 | 人设、主体状态、记忆、AI 回复、AI 私域 |
| 平台数据 | 平台运行、配置、权限、审计和适配所需的数据 | 软件事件、权限状态、设备连接、模型服务配置 |

敏感等级与数据分类分开表达。账号身份、对话和普通主体设定至少按敏感数据处理；健康、财务、生理期、亲密内容、AI 私域正文和设备高风险数据按高敏感数据处理；密钥、密码和验证码只保存安全引用或验证结果，不进入普通业务记录。

## 通用建模规则

### 标识与归属

- 每个核心对象使用稳定、不可从业务内容推导的唯一标识。
- 除 `User` 自身外，所有用户私有对象必须能够追溯到 `user_id`。
- 所有主体级对象必须同时保存 `user_id` 和 `subject_id`，不能只依赖级联查询推断用户归属。
- 用户级共享对象可以不绑定单一主体，但必须显式记录 `scope_level=user`；主体级使用时通过授权范围关联主体。
- 更换模型、头像、名称或设备不改变 `user_id` 和 `subject_id`。

### 时间与来源

- 保存创建时间、更新时间或发生时间时，以统一时间基准记录，展示时再使用用户时区。
- 由消息、事件、工具、导入或连续性结果产生的数据必须保存来源类型和来源引用。
- 摘要、记忆和状态更新需要能够追溯到原始消息、事件或外部结果，不能只保存不可解释的结论。

### 版本与当前状态

- `SubjectState`、`MessageVersion` 和 `Event` 采用保留历史的设计，不用原地覆盖抹去重要变化。
- “当前版本”通过当前指针、状态标记或单调版本号表达；当前 Message 物理子集采用 `messages.current_version_id` 单一指针，不在版本行再保存第二份当前标记。
- 历史记录仍受用户导出、删除、保留期限和法律要求约束，不能成为永久不可见黑箱。

### 删除与保留

- 逻辑状态至少能够区分：有效、隐藏、停用、等待删除和已删除。
- 删除用户、主体或单项数据时，先计算影响范围，再执行对应生命周期变化。
- 审计、消息隐藏版本和事件是否立即物理删除，等待隐私与保留策略 ADR；用户界面必须明确显示结果状态。
- 共享的 `Device` 或 `APIProvider` 不因删除单个主体而自动删除，只撤销该主体的关联和权限。

| `Model` | 保存 Provider 下的具体模型与能力标签 | 平台数据、用户配置数据 | `user_id` + `api_provider_id` |

## User（用户）

### 作用与分类

`User` 表示平台账号，是认证、用户级设置、数据权利和其他私有对象的根归属。

- 分类：用户数据、平台数据
- 主键：`user_id`
- 不包含：密码明文、邮箱验证码原文、付款密码、API Key

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `user_id` | 用户稳定唯一标识 |
| `display_name` | 用户在平台内的显示名称，可为空 |
| `primary_email` | 已验证的主要邮箱，按敏感数据处理 |
| `login_identities` | 登录方式集合，包括方式、外部身份标识、安全引用和验证状态 |
| `status` | `pending`、`active`、`suspended`、`disabled` 或 `deletion_pending` |
| `locale` | 语言与地区偏好 |
| `timezone` | 展示时间使用的用户时区 |
| `agreement_versions` | 已确认的协议版本和确认时间 |
| `created_at` | 账号创建时间 |
| `updated_at` | 账号资料或状态更新时间 |
| `deletion_state` | 账号删除请求、处理阶段和结果摘要 |

### 约束与关系

- 同一登录来源的外部身份只能映射到一个有效用户。
- 一个用户可以拥有多个 `Subject`、`Conversation`、`Permission`、`Device` 和 `APIProvider`。
- 登录身份不自动授予设备、模型或外部服务权限。

## UserSpace（用户空间）

### 作用与分类

`UserSpace` 是每个用户唯一的数据归属根，用于承载开发期身份状态和当前助手选择。它不保存助手设定、状态、私域正文、对话或生活正文，也不承担登录会话职责。

- 分类：用户数据、平台数据
- 主键：`space_id`
- 所属：`user_id` 一对一唯一

### 当前物理字段

| 字段 | 作用 |
| --- | --- |
| `space_id` | 平台生成的空间唯一 ID；既有用户迁移使用稳定回填 ID |
| `user_id` | 唯一所属用户 |
| `identity_mode` | 当前固定 `development_unverified`，明确表示未连接真实认证 |
| `status` | `active`、`suspended` 或 `disabled` |
| `current_assistant_id` | 可空的当前助手指针，必须属于同一用户 |
| `created_at` / `updated_at` | 空间创建与当前助手变化时间 |

### 约束与关系

- User 与 UserSpace 在同一事务创建；一个用户不能有多个空间。
- 新用户首个 Subject 在当前指针为空时成为当前助手；迁移按最早活动 Subject 稳定回填。
- 当前助手只是用户界面/请求上下文选择，不改变 Subject 身份，也不复制、合并或重写 Assistant Global Settings、Assistant Private Space、SubjectState、Conversation、Event 或生活数据。
- 统一隔离查询以 UserSpace 为用户根，但实际记录仍按各模块的 `user_id + assistant_id + resource_id` 复合条件读取；高敏感资源还必须经过 Permission 与 Security Policy。

## Subject（AI 主体）

### 作用与分类

`Subject` 表示一个可长期延续的 AI 主体。模型只是可替换能力，不能代替主体标识。

- 分类：AI 主体数据、用户数据
- 主键：`subject_id`
- 所属：必须关联唯一 `owner_user_id`

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `subject_id` | 主体稳定唯一标识 |
| `owner_user_id` | 主体所属用户 |
| `name` | 主体名称 |
| `avatar_asset_ref` | 头像资源引用，不直接规定存储介质 |
| `persona` | 主体人设和基础定位 |
| `global_settings` | 长期生效的结构化全局设定 |
| `expression_style` | 表达方式与沟通偏好 |
| `relationship_definition` | 主体与用户的关系定义 |
| `long_term_requirements` | 用户明确设置的长期要求 |
| `prohibitions` | 主体禁止事项，不得削弱平台最低安全规则 |
| `memory_policy` | 记忆保存方式和默认上下文参与规则 |
| `current_state_id` | 当前有效 `SubjectState` 版本的逻辑引用 |
| `status` | `active`、`archived`、`disabled` 或 `deletion_pending` |
| `created_at` / `updated_at` | 创建与设定更新时间 |

### 当前开发物理子集

- `subjects.name` 与 `subjects.avatar_ref` 继续作为助手名称和头像/标识的唯一事实来源，避免 Global Settings 与现有 Subject/Dashboard API 双写漂移。
- `assistant_global_settings` 以 `(owner_user_id, subject_id)` 为主键并通过复合外键一对一绑定 Subject，保存 `personality_description`、`expression_style_json`、`relationship_definition`、`long_term_requirements_json`、`prohibitions_json`、创建和更新时间。
- 创建新 Subject 时同步创建空白默认设定；迁移为既有 Subject 回填空白结构，不从 `basic_settings_json` 推断人格或关系。
- 全局设定实际变化与最小 `subject_updated` Event 同事务提交；Event 只记录变化字段名，不复制设定正文。
- Global Settings 是允许用户明确更新的长期配置；SubjectState 是带来源、不可变追加的动态状态版本。两者不互相写入或覆盖。

### 约束与关系

- 主体不能脱离所属用户单独存在或被跨用户读取。
- 同一用户的多个主体，其状态、记忆、会话、私域和设备权限不得自动混合。
- 一个主体拥有多个状态版本、记忆、事件、会话和私域条目。
- 删除主体不自动删除用户级 `Device` 或 `APIProvider`，只解除主体作用范围。

## SubjectState（主体状态）

### 作用与分类

`SubjectState` 保存主体在某一时点的状态快照，使状态不依赖模型从长对话中重新猜测。

- 分类：AI 主体数据
- 主键：`subject_state_id`
- 归属：`user_id` + `subject_id`
- 版本策略：一个主体可以有多个不可覆盖的状态版本，同时只能有一个当前版本

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `subject_state_id` | 状态版本唯一标识 |
| `user_id` / `subject_id` | 用户和主体双重归属 |
| `state_version` | 主体内单调递增的状态版本 |
| `current_state` | 当前状态的结构化摘要 |
| `emotion` | 当前主要情绪或情绪集合 |
| `intensity` | 情绪或状态强度；量表和精度等待实现 ADR |
| `change_reason` | 本次状态变化的可解释原因 |
| `unresolved_event_ids` | 仍需延续处理的事件引用集合 |
| `continuity_constraints` | 下一轮需要保持的连续性约束 |
| `source_type` / `source_ref` | 消息、事件、导入或连续性结果来源 |
| `supersedes_state_id` | 被当前版本替代的前一状态 |
| `is_current` | 是否为当前有效版本 |
| `created_at` | 状态版本形成时间 |

### 约束与关系

- 状态写入必须校验 `user_id`、`subject_id` 与来源归属一致。
- 窗口重置不删除或重置 `SubjectState`。
- continuity-engine 可以通过稳定接口提供状态结果，但平台只保存输入、结果与来源，不保存其内部算法。

### 当前开发物理子集

- `subject_states` 保存结构化 `current_state_json`、情绪、`0—1` 强度、变化原因、连续性约束 JSON 以及 MessageVersion、Event 或 ConversationSummary 三类强归属来源。
- 状态版本在同一主体内单调递增，数据库触发器禁止直接 UPDATE 或 DELETE。
- `subject_state_heads` 使用 `(user_id, subject_id)` 唯一行选择当前状态；更新指针不改变历史状态内容。
- `subject_state_unresolved_events` 按顺序保存同主体 Event 引用，状态、引用和当前指针在同一事务提交。
- 当前没有模型响应解析、自动状态演化、`supersedes_state_id` 字段或 continuity-engine 调用；`isCurrent` 由当前指针在查询时计算。

## Memory（记忆）

### 作用与分类

`Memory` 保存可长期引用、可追溯并受用户控制的主体记忆。

- 分类：AI 主体数据、用户数据
- 主键：`memory_id`
- 归属：`user_id` + `subject_id`

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `memory_id` | 记忆唯一标识 |
| `user_id` / `subject_id` | 用户和主体双重归属 |
| `memory_kind` | 长期记忆及未来经确认的记忆类别 |
| `content` | 记忆正文或结构化内容，按敏感数据处理 |
| `summary` | 用于检索和上下文装配的最小摘要 |
| `source_type` / `source_ref` | 对话、消息、事件、导入或本地来源 |
| `occurred_at` | 原始事情发生时间 |
| `recorded_at` | 记忆写入平台时间 |
| `include_in_context` | 用户是否允许该记忆参与上下文 |
| `visibility_scope` | 可见主体、模块和使用范围 |
| `sensitivity` | 普通、敏感或高敏感 |
| `status` | `active`、`excluded`、`archived` 或 `deletion_pending` |
| `retention_state` | 保留、导出和删除状态 |

### 约束与关系

- `include_in_context=false` 时不得进入模型或连续性上下文，但不等于删除记录。
- 记忆必须能够追溯到来源；导入内容需要同时保存导入批次和原来源说明。
- 不同主体的记忆不得因内容相似而自动合并。

## LifeManagement（生活管理）

### 作用与分类

生活管理保存用户明确录入的财务、月历、身体和本地记忆数据。它属于 User Space，同时按主体划分使用范围；不会写入 Assistant Private Space。

- 分类：用户数据；财务、健康、生理期、亲密和记忆正文为高敏感数据
- 归属：所有物理记录必须同时保存 `user_id + subject_id`
- 安全范围：`life_data` 的 `finance`、`calendar`、`body`、`local-memory`

### 当前物理对象

| 对象 | 主键与唯一性 | 核心字段与约束 |
| --- | --- | --- |
| `life_financial_records` | `financial_record_id`；复合归属唯一 | 收入/支出、分类、`amount_minor > 0`、币种、发生时间、备注 |
| `life_budgets` | `budget_id`；用户/主体/月/分类唯一 | 整数预算、币种、提醒规则 JSON、创建/更新时间 |
| `life_calendar_entries` | `calendar_entry_id`；复合归属唯一 | 四类记录、标题、开始/结束、备注、提醒规则 |
| `life_body_records` | `body_record_id`；复合归属唯一 | 至少一个体重/三围值、显式建议、测量时间 |
| `life_body_goals` | `body_goal_id`；每个用户/主体最多一个 | 至少一个目标值、目标日期、备注 |
| `local_memories` | `memory_id`；复合归属唯一 | 标题、正文、是否参与 Context、导出标记、时间 |

金额使用最小货币单位整数，API 才格式化为两位小数。预算和身体目标使用 Upsert，但保持稳定 ID 与最初创建时间。身体建议只接受调用方显式文本，不保存模型来源或医疗结论。本地记忆 Context 投影只读取 `participates_in_context=1`，不会自动合并到通用 Conversation Context。

当前没有支付/银行引用、穿戴设备来源、提醒执行状态、删除状态或真实导出文件。生活记录写入与最小 Event 同事务提交，Event 不复制敏感字段。

## Event（软件事件）

### 作用与分类

`Event` 把 Vio Live 中的重要软件变化保存为最小、结构化、可追溯的事实，让 AI 或 continuity-engine 在获得授权且确有需要时感知变化。

- 分类：平台数据；事件摘要可能引用用户数据或 AI 主体数据
- 主键：`event_id`
- 归属：必须有 `user_id`；主体级事件必须有 `subject_id`

### 事件类型

当前开发实现已落地以下十八种稳定事件名：

| `event_type` | 当前范围 |
| --- | --- |
| `appearance_changed` | 头像、主题等外观变化 |
| `subject_updated` | AI 主体名字、头像引用或基础设定变化 |
| `permission_created` | Permission 创建 |
| `permission_changed` | Permission 修改或单次消费 |
| `permission_revoked` | Permission 软删除/撤销 |
| `confirmation_required` | 安全请求需要具体确认；不表示执行 |
| `life_record_created` | 新增生活记录 |
| `life_event_created` | 生活管理记录创建或变化，不复制敏感字段 |
| `budget_changed` | 预算新增或更新，不复制金额与分类 |
| `health_record_updated` | 身体指标或目标变化，不复制数值与建议 |
| `device_changed` | 平台设备注册、注册状态、主体授权或操作请求；当前不表示真实连接、状态同步或执行 |
| `conversation_created` | 创建主体范围的对话容器，不复制标题 |
| `message_created` | 创建稳定消息和初始版本，不复制正文 |
| `message_updated` | 用户消息追加编辑版本，只保存 ID 和版本关系 |
| `message_regenerated` | 主体消息追加重生成记录，不复制正文或调用模型 |
| `private_space_created` | 创建空 AI Private Space，不复制正文 |
| `private_memory_updated` | 私域认知、长期偏好、工作或笔记版本变化，不复制正文 |
| `private_state_changed` | 私域 AI 状态版本或 Space 状态变化，不复制正文 |

逻辑规划中的更宽分类如下。`capability_changed`、`life_module_changed` 和 `data_changed` 尚未成为当前接口可写入的事件名，后续扩展必须经过契约和迁移评审。

| `event_type` | 范围 |
| --- | --- |
| `appearance_changed` | 名字、头像、主题、气泡等外观变化 |
| `permission_changed` | 授权、拒绝、撤销或禁止询问 |
| `capability_changed` | 模型、MCP、Skill、插件或 Tool 状态变化 |
| `life_module_changed` | 月历、预算、体重等生活模块变化 |
| `device_changed` | 设备连接、状态、授权或高风险变化 |
| `data_changed` | 导入、删除、恢复、迁移等数据变化 |

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `event_id` | 事件唯一标识 |
| `user_id` / `subject_id` | 用户归属和可选主体范围 |
| `scope_level` | `user` 或 `subject`，决定 `subject_id` 是否必填 |
| `event_type` | 当前二十四种事件类型之一；后续类型需版本化扩展 |
| `event_action` | 类型内的具体动作 |
| `actor_type` / `actor_ref` | 用户、平台、主体或外部能力来源 |
| `source_type` / `source_ref` | 原始业务对象和版本引用 |
| `summary` | 可供理解的最小脱敏摘要 |
| `payload` | 结构化最小变化，不保存秘密原文 |
| `visibility_scope` | 哪些主体、模块或管理流程可以读取 |
| `sensitivity` | 事件的敏感等级 |
| `correlation_id` | 串联同一操作产生的多个事件和审计记录 |
| `occurred_at` / `recorded_at` | 发生与入库时间 |
| `processing_status` | 未处理、已忽略、已消费或处理失败 |

### 约束与关系

- 已记录事件不原地改写；更正通过新事件或状态标记表达。
- API Key、付款密码、验证码、完整证件号码和不必要的敏感正文不得进入 `summary` 或 `payload`。
- 事件出现不代表自动调用模型，也不授予新权限。

### 当前开发物理子集

- 物理字段为 `event_id`、`user_id`、可选 `subject_id`、`event_type`、`source_type`、可选 `source_ref`、`occurred_at`、`recorded_at`、`event_data_json`、`summary` 和 `status`。
- `status` 当前写入默认值 `pending`；`consumed`、`ignored` 和 `failed` 只作为未来处理状态保留，本阶段没有更新接口。
- 主体级事件通过 `(user_id, subject_id)` 复合外键保证主体属于用户。
- 事件按发生时间倒序读取；查询支持主体、事件类型、状态、起止时间和数量限制。
- 逻辑模型中的 `scope_level`、`event_action`、`actor_*`、`visibility_scope`、`sensitivity` 和 `correlation_id` 尚未物理实现。

## Conversation（对话）

### 作用与分类

`Conversation` 是用户与特定主体进行对话的容器，管理窗口、分支和当前可见边界。

- 分类：用户数据、AI 主体数据
- 主键：`conversation_id`
- 归属：`user_id` + `subject_id`

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `conversation_id` | 对话唯一标识 |
| `user_id` / `subject_id` | 用户和主体双重归属 |
| `title` | 会话名称 |
| `status` | `active`、`archived`、`hidden` 或 `deletion_pending` |
| `current_branch_id` | 当前选择的对话分支 |
| `current_message_version_id` | 当前可见的最后消息版本 |
| `context_mode` | 精简、标准、完整或自定义上下文模式 |
| `preferred_provider_id` | 可选的用户手动模型配置引用，不代表已执行调用 |
| `last_activity_at` | 最近对话活动时间 |
| `created_at` / `updated_at` | 创建与元数据更新时间 |

### 约束与关系

- 一个对话只能属于一个用户和一个主体。
- 对话包含多个稳定 `Message`，每个 Message 关联多个 `MessageVersion`；当前聊天流只选择当前指针指向的版本。
- 重置只改变对话窗口的当前可见边界，不删除主体状态和长期记忆。

### 当前开发物理子集

- 当前状态只创建 `active`，并为未来 `archived` 预留数据库值；没有状态修改接口。
- `last_activity_at` 在新增消息或追加版本时与数据和 Event 同事务更新。
- 当前没有 `current_branch_id`、`context_mode`、Provider 引用或重置边界字段；它们仍是逻辑规划。

## Message（逻辑消息）

### 作用与分类

`Message` 是会话时间线上的稳定逻辑记录，使同一条用户或主体消息可以拥有多个不可变正文版本，而不改变时间线位置或发送者。

- 分类：用户数据、AI 主体数据、平台版本数据
- 主键：`message_id`
- 归属：`user_id` + `subject_id` + `conversation_id`

### 当前开发物理字段

| 字段 | 作用 |
| --- | --- |
| `message_id` | 跨版本保持稳定的消息标识 |
| `user_id` / `subject_id` / `conversation_id` | 完整复合归属 |
| `sender_type` | `user`、`subject` 或 `system`；版本追加时不可改变 |
| `status` | 当前只创建 `active`，没有删除或隐藏接口 |
| `sequence_number` | 同一会话内单调递增的线性消息顺序 |
| `current_version_id` | 指向同一消息当前可见版本的复合外键 |
| `created_at` / `updated_at` | 初始创建和当前版本切换时间 |

正文只存在于 `MessageVersion`，Message API 通过当前版本联结返回 `content`，避免双写和覆盖历史。

## MessageVersion（消息版本）

### 作用与分类

`MessageVersion` 以不可覆盖的版本记录支持用户消息编辑、AI 回复重生成、删除、分支和窗口重置。

- 分类：用户数据、AI 主体数据、平台版本数据
- 主键：`message_version_id`
- 归属：`user_id` + `subject_id` + `conversation_id`

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `message_version_id` | 单个版本唯一标识 |
| `message_id` | 同一逻辑消息跨版本保持稳定的标识；重置标记可使用专用记录标识 |
| `conversation_id` | 所属对话 |
| `user_id` / `subject_id` | 用户和主体双重归属 |
| `version_number` | 同一逻辑消息内单调递增版本 |
| `author_type` | `user`、`subject` 或 `system` |
| `record_kind` | `content`、`deletion_marker`、`branch_marker` 或 `reset_marker` |
| `change_reason` | 原始、编辑、重生成、删除、分支或重置原因 |
| `content` | 当前版本内容；删除或重置标记可以为空 |
| `content_format` | 文本、图片引用、文件引用、语音引用或结构化内容 |
| `parent_version_id` | 上一版本或分支起点 |
| `branch_id` | 所属分支标识 |
| `provider_id` | AI 生成版本使用的可选 `APIProvider` 引用 |
| `context_revision_ref` | 生成时使用的上下文版本引用 |
| `is_current` / `visibility_state` | 当前选择和普通聊天流可见状态 |
| `created_at` | 版本形成时间 |

### 约束与关系

- 已形成的版本不原地修改；编辑和重生成创建新版本。
- 同一逻辑消息在同一分支上只能有一个当前版本。
- 删除先通过删除标记使普通聊天流不可见，后续物理清理由保留策略决定。
- `reset_marker` 保存清空范围和时间，不级联删除 `SubjectState` 或 `Memory`。

### 当前开发物理子集

- 当前只实现 `original`、`edited`、`regenerated` 三种文本版本；删除、分支和重置标记尚未落库。
- 初始版本固定为版本 1 且没有父版本；编辑和重生成必须追加更高版本并引用同一 Message 的当前父版本。
- 用户编辑只适用于 `sender_type=user`，重生成记录只适用于 `sender_type=subject`；system 消息本阶段不能追加版本。
- API 要求 `baseVersionId` 匹配当前指针，陈旧版本返回冲突；版本号分配和指针切换在 `BEGIN IMMEDIATE` 事务中完成。
- 数据库阻止普通 UPDATE 和 DELETE MessageVersion；未来用户删除权与保留策略必须通过受控迁移/治理流程实现，而不是绕过版本历史。
- 当前没有 Provider、上下文修订、内容格式、分支或可见性字段。主体内容由开发调用方提交，不表示真实模型调用。

## ConversationSummary（会话摘要）

### 作用与分类

`ConversationSummary` 保存开发调用方提交的窗口摘要，使同一主体切换 Conversation 后可以读取最小历史重点，而不加载全部消息。

- 分类：用户数据、AI 主体数据、平台版本数据
- 主键：`summary_id`
- 归属：`user_id` + `subject_id` + `conversation_id`

### 当前开发物理字段

| 字段 | 作用 |
| --- | --- |
| `summary_id` | 摘要稳定唯一标识 |
| `user_id` / `subject_id` / `conversation_id` | 完整复合归属 |
| `summary_version` | 同一 Conversation 内单调递增版本 |
| `summary_text` | 调用方提交的摘要正文，最多 16384 字符 |
| `status` | 当前固定为 `active` |
| `created_at` | 摘要保存时间 |

`conversation_summary_sources` 为每个摘要保存有序来源，当前支持：

- `message_version`：同一 Conversation 内的 `message_id + message_version_id`。
- `event`：同一用户和主体范围内的 `event_id`。

### 约束与关系

- 每个摘要至少包含一个来源，重复来源被拒绝；摘要和全部来源在同一事务提交。
- 数据库复合外键阻止跨用户、跨主体或跨 Conversation 的 MessageVersion 引用，也阻止跨主体 Event 引用。
- 摘要和来源不可原地修改或直接删除；正式保留与用户删除流程仍待生产治理决策。
- 跨窗口读取排除当前 Conversation，只返回相同用户/主体下每个其他 Conversation 的最新摘要并限制数量。
- 当前不保存模型、Provider、Token、提示词或自动生成元数据；摘要内容不代表 AI 生成。

## Permission（权限）

### 作用与分类

`Permission` 保存主体对能力、设备、数据类型和动作的授权决定及有效范围。

- 分类：平台数据、用户授权数据
- 主键：`permission_id`
- 归属：`user_id` + 用户级或主体级作用范围

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `permission_id` | 权限决定唯一标识 |
| `user_id` / `subject_id` | 用户归属和可选主体范围 |
| `scope_level` | `user` 或 `subject` |
| `target_type` / `target_ref` | Tool、设备、外部服务、数据类型或其他能力 |
| `action` | 读取、写入、执行、控制、导出、删除等具体动作 |
| `permission_level` | 当前为 `always_allow`、`ask_every_time`、`allow_once`、`denied`、`forbidden_ask` |
| `allowed_scope` | 数据范围、设备范围或能力参数范围 |
| `valid_from` / `valid_until` | 授权有效时间 |
| `session_id` | 会话授权对应的会话；其他档位为空 |
| `can_request` | 是否允许主体再次申请 |
| `status` | 当前为 `active`、`inactive`、`consumed` 或 `deleted` |
| `decision_source` | 用户确认、平台最低安全规则或管理限制 |
| `supersedes_permission_id` | 被新决定替代的上一权限记录 |
| `revoked_at` / `revoked_reason` | 撤销信息 |
| `created_at` | 权限决定形成时间 |

### 约束与关系

- 权限目标、动作、范围和有效期必须同时判断，不能只检查总开关。
- `forbidden_ask` 同时禁止执行和再次申请；`denied` 拒绝执行但允许后续申请。
- 高风险操作即使处于允许状态，仍需单独的具体操作确认记录。
- 撤销后立即停止新调用；历史权限决定保留受控审计关系。

### 当前开发物理子集

- 当前字段为 `permission_id`、`user_id`、`subject_id`、`resource_type`、`resource_id`、`action`、`permission_level`、`status`、`created_at` 和 `updated_at`。
- 当前所有规则必须绑定主体；`(user_id, subject_id)` 复合外键确保主体属于该用户。
- 资源类型限定为 `memory`、`tool`、`mcp`、`skill`、`device`、`api`、`private_domain`、`life_data`。
- 操作限定为 `read`、`write`、`execute`、`control`、`connect`、`export`、`delete`、`manage`。
- 同一用户、主体、资源类型、资源 ID 和操作只允许一个 `active` 或 `inactive` 当前规则。
- Checker 只匹配 `active` 规则；无规则默认拒绝。独立 Checker 首次判断会消费 `allow_once`；Security 预检不消费，安全链满足后才变为 `consumed`。删除变为 `deleted`。
- 创建、实际更新/单次消费、删除分别与 `permission_created`、`permission_changed`、`permission_revoked` Event 同 SQLite 事务提交。
- `scope_level`、允许范围、Permission 自身的会话档位/有效期、决定来源、替代链和撤销原因仍未物理实现；当前短时授权属于独立 Security Policy 层。

## SecurityPolicy 与 UserSecurityPreferences（自定义安全栏）

### 作用与分类

`SecurityPolicy` 在基础 Permission 之后表达用户对某类资源、动作和风险的安全规则；`UserSecurityPreferences` 保存用户级默认值和范围。两者只能收紧 Permission，不能授予基础权限或降低平台高风险底线。

- 分类：平台数据、用户安全偏好数据
- 主键：`policy_id`；偏好以 `user_id` 一对一
- 归属：必须绑定 `user_id`

### 当前物理字段

| 对象 | 字段 | 作用 |
| --- | --- | --- |
| SecurityPolicy | `policy_id` / `user_id` | 策略标识与用户归属 |
| SecurityPolicy | `resource_type` / `action_type` / `risk_level` | 精确匹配八类资源、八种动作和四级有效风险 |
| SecurityPolicy | `rule` | `always_allow`、`session_allow`、`always_confirm`、`deny`、`deny_without_confirm` |
| SecurityPolicy | `status` / `created_at` / `updated_at` | `active` / `deleted` 与版本时间 |
| UserSecurityPreferences | `default_security_level` | 只能抬高平台风险分类 |
| UserSecurityPreferences | `high_risk_operation_policy` | `always_confirm`、`deny` 或 `deny_without_confirm` |
| UserSecurityPreferences | `auto_confirmation_scopes_json` | 只允许低/中风险的资源/动作/最大风险范围 |
| UserSecurityPreferences | `forbidden_scopes_json` | 禁止的资源类型与动作范围 |
| SecurityPolicySessionGrant | 用户/主体/策略版本/安全会话/资源/动作/风险 | 确认后生成的精确短时授权作用域 |
| SecurityPolicySessionGrant | `granted_at` / `expires_at` | 30 分钟有效窗口 |

### 约束与关系

- 每个用户的同一资源类型、动作和风险只能有一条活动策略；删除保留 `deleted` 记录和审计。
- 禁止范围优先拒绝；`deny` 与 `deny_without_confirm` 都不执行资源，后者同时禁止询问。
- `always_allow`、自动确认和 `session_allow` 不能跳过 `high` / `critical` 逐次确认。
- 策略更新以 `updated_at` 形成版本边界，使旧 Confirmation 与短时授权失配。
- `security_session_id` 只是开发期不透明关联标识，不是认证凭证。

## Confirmation（操作确认）

### 作用与分类

`Confirmation` 表示用户对某一次具体安全请求的批准或拒绝。它补充 Permission，但不能改变或绕过 Permission，也不表示真实动作已经执行。

- 分类：平台数据、用户授权数据
- 主键：`confirmation_id`
- 归属：`user_id` + `subject_id` + 完整操作作用域

### 当前物理字段

| 字段 | 作用 |
| --- | --- |
| `confirmation_id` | 确认唯一标识 |
| `user_id` / `subject_id` | 用户与主体双重归属 |
| `operation_type` | 安全操作类型 |
| `resource_type` / `resource_id` / `action` | 本次确认绑定的具体资源与动作 |
| `permission_id` / `permission_level` / `permission_updated_at` | 防止权限变化后复用的 Permission 快照 |
| `security_policy_id` / `security_policy_updated_at` | 防止策略变化后复用的 Security Policy 快照 |
| `security_session_id` | 可选开发期安全会话作用域；不是身份凭证 |
| `confirmation_mode` | 持久记录只使用 `every_time` 或 `user_defined`；`not_required` 不落表 |
| `risk_level` | `low`、`medium`、`high` 或 `critical` |
| `policy_fingerprint` | 安全策略、敏感分类和风险依据的不可逆规范化指纹 |
| `confirmation_reason` / `risk_description` | 平台生成的确认原因与风险说明 |
| `user_choice` | 用户决定后的 `approve` 或 `reject` |
| `status` | `pending`、`approved`、`rejected`、`consumed`、`expired` |
| `requested_at` / `expires_at` / `decided_at` / `consumed_at` | 请求、五分钟有效期、决定和使用时间 |

### 约束与关系

- 确认必须完全匹配用户、主体、操作类型、资源、动作、风险、Permission 快照、Security Policy 版本、偏好版本和开发期安全会话。
- 批准状态只能成功转为 `consumed` 一次；已拒绝或已消费记录不能放行。
- 高风险/极高风险为 `every_time`；用户偏好和策略不能降低该平台底线。
- 当前确认固定五分钟过期，策略会话授权固定 30 分钟；仍没有可配置期限、后台清理或正式认证会话联动，生产接入前必须补充认证来源和清理策略。

## AuditLog（安全审计）

### 作用与分类

`AuditLog` 保存安全治理所需的最小事实，与供平台感知的软件 Event 分离。

- 分类：平台数据，可引用用户数据或 AI 主体范围
- 主键：`audit_log_id`
- 归属：`user_id` + 可选 `subject_id`

### 当前物理字段

| 字段 | 作用 |
| --- | --- |
| `audit_log_id` | 审计记录唯一标识 |
| `user_id` / `subject_id` | 请求范围所属用户和可选操作主体；当前不代表已认证操作者身份 |
| `operation_type` | 权限变化、API 配置、隐私访问等操作类型 |
| `resource_type` / `resource_id` / `action` | 最小资源引用和动作，不保存资源正文 |
| `risk_level` | 安全判断风险等级 |
| `permission_decision` / `confirmation_mode` | 当时的 Permission 结果和确认要求 |
| `result` / `reason_code` | 允许、拒绝、确认或变更结果及固定脱敏原因码 |
| `confirmation_id` | 可选的具体确认引用 |
| `occurred_at` | 审计事实发生时间 |

### 约束与关系

- 只提供内部写入和按路径 `user_id` 限定范围的只读查询，不提供客户端创建、更新或删除接口；该范围限制不是身份认证，认证接入前不得公开部署。
- 不包含任意 payload 或 details JSON；资源仅接受平台不透明 ID，并用启发式规则拦截常见凭据形态。该拦截不是完整 DLP，生产阶段还需可信资源注册表和专用秘密扫描。
- 按接口契约，API Key、身份/支付原文、私密记录正文和 AI 私域正文不得作为资源 ID 或其他审计字段传入；当前结构没有 payload/正文列并会启发式拦截常见凭据形态，但这不构成完整 DLP 保证。
- 当前记录 Permission 变更、Security Policy/安全偏好变更、APIProvider 配置变更、安全检查和确认决定。
- 生产保留期限、法定留存、用户可见范围和删除政策仍待安全与法律审查。

## SensitiveDataClassification（敏感数据分类）

当前 SensitiveData 模块只在代码中定义 `api_key`、`identity_information`、`payment_information`、`private_record`、`ai_private_domain` 五类元数据，每类包含风险等级、未来存储要求和固定的 `contentAccepted=false`。分类查询接口没有正文写入入口；它不是敏感正文表，也不保存分类实例、秘密引用或真实值。这一边界不代表整个平台没有账号邮箱等身份字段。

## Device（设备）

### 作用与分类

`Device` 保存用户连接的手机、家电、穿戴、摄像头、门锁或其他设备的统一平台表示。

当前物理实现只覆盖安全的平台注册子集：七类 Device Registry、四类 Device Capability、同用户主体 Permission 授权和未执行操作日志。注册状态与物理连接状态分离；响应固定标记未连接、状态未观测，不保存本节规划中的位置、外部设备引用、凭据、实际状态、风险档位、最近在线时间或真实授权集合。后续接入不得把当前注册记录迁移解释为已经连接。

- 分类：平台数据；名称、位置和状态可能属于用户数据或高敏感数据
- 主键：`device_id`
- 归属：`owner_user_id` + 主体授权范围

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `device_id` | 平台内设备唯一标识 |
| `owner_user_id` | 设备所属用户 |
| `display_name` | 用户可识别的设备名称 |
| `category` | 手机、家电、穿戴、摄像头、门锁、亲密设备或其他 |
| `location_label` | 房间或位置标签，按敏感数据处理 |
| `adapter_type` / `external_device_ref` | 适配器类型和外部设备标识，不包含凭据 |
| `credential_ref` | 安全密钥库中的凭据引用，前端和普通导出不可读取原文 |
| `connection_status` | 未连接、已连接、离线、错误或已撤销 |
| `state_summary` | 最近一次允许保存的设备状态摘要 |
| `capabilities` | 读取状态、开启、关闭、设置模式、立即停止等能力描述 |
| `risk_level` | 普通、敏感或高风险 |
| `authorized_subject_ids` | 获得明确授权的主体关系集合 |
| `last_seen_at` | 最近一次有效状态时间 |
| `status` | 有效、停用、撤销或等待删除 |
| `created_at` / `updated_at` | 平台记录时间 |

### 约束与关系

- 一个用户可以连接多个设备；一个设备可以授权给多个同用户主体。
- 主体授权不能跨越设备所有者的用户边界。
- 摄像头、门锁、健康穿戴和亲密设备需要更高敏感等级、单独日志和立即停止能力。
- 当前设备操作统一通过 Permission → Security → Confirmation；操作日志关联最小 AuditLog 与 `device_changed`，所有设备与厂商调用固定未执行。

### 作用与分类

`PrivateDomain` 保存主体暂未主动公开的私域目录、正文、可见性和开放结果。

- 分类：AI 主体数据、高敏感用户相关数据
- 主键：`private_domain_id`
- 归属：`user_id` + `subject_id`

### 逻辑字段

| 字段 | 作用 |
| --- | --- |
| `private_domain_id` | 私域条目唯一标识 |
| `user_id` / `subject_id` | 用户和主体双重归属 |
| `content_type` | 对用户的印象、小日记、未说出口的话、纪念与惊喜或自我观察 |
| `directory_title` | 默认可见的模糊标题 |
| `directory_summary` | 不泄露正文的最小目录摘要 |
| `content` | 默认锁定的私域正文 |
| `visibility_state` | 锁定、全部开放、部分开放、暂时拒绝或延后开放 |
| `disclosure_scope` | 已允许查看的具体范围 |
| `visibility_policy` | 是否允许再次查看、申请或满足条件后开放的规则引用 |

- 内容可见性不影响用户对相关数据的导出、删除和停用权。
- 该对象不定义 continuity-engine 如何生成或判断私域内容。

### 当前开发物理子集

- `assistant_private_spaces` 使用 `space_id` 主键，保存 `user_id`、`assistant_id`、`active|inactive` 状态和时间；`assistant_id` 当前映射 Subject，`(user_id, assistant_id)` 唯一。
- `assistant_private_content_versions` 使用稳定 `content_id` 与唯一 `content_version_id`，保存五类 `content_type`、递增 `version_number`、`parent_version_id`、JSON 正文、`created|updated` 变化原因和固定 `explicit_api_input` 来源。
- 五类物理内容为 AI 状态、认知、长期偏好、工作记录和私有笔记。数据库触发器禁止更新或删除历史版本；当前版本按最大版本号读取。
- User Space 与 Assistant Private Space 不共表；每次内容查询限定 `user_id + assistant_id + space_id`。通用 Context 不自动读取私域。
- 创建空 Space 不接收正文，用于生成精确 `private_domain` Permission 的资源 ID。后续 `read`、`write`、`manage`、`export` 均经过 Security Policy 和高风险 Confirmation。
- 当前没有目录标题、开放状态、披露范围、来源引用集合、删除字段或真实导出正文。Export Manifest 只返回版本元数据，固定不生成文件。
- Event 与 AuditLog 不复制正文；私域 API 拒绝凭据/身份秘密字段。开发 SQLite 尚无生产加密，不得作为公开存储方案。

## ModelRoutingRule（模型路由规则）

### 作用与分类

`ModelRoutingRule` 保存一个用户对某类任务明确选择的默认模型和可选备用模型。它是平台配置，不是模型执行记录，也不绑定或改变某个 Subject。

- 分类：平台数据、用户配置数据
- 主键：`routing_rule_id`
- 归属：`owner_user_id`
- 不包含：Context、提示词、回复、状态更新、密钥或 Token

### 当前物理字段

| 字段 | 作用 |
| --- | --- |
| `routing_rule_id` | 路由规则唯一标识 |
| `owner_user_id` | 规则所属用户 |
| `task_type` | `chat`、`long_text`、`image`、`video`、`audio`、`search` |
| `default_model_id` | 默认模型引用 |

## 主动交互与 Token 控制（当前开发物理子集）

### WakeRule

- 分类：用户数据、AI 主体数据、平台配置数据
- 主键：`wake_id`
- 归属：`user_id + subject_id`
- 字段：`wake_type`（voice/desktop/schedule/event）、`status`、`trigger_condition_json`、`authorization_status`、创建/更新时间
- 边界：应用内授权不等于麦克风或系统权限；结构只保存配置，不保存音频或执行结果。

### ProactivePromptRule / ProactivePromptRecord

- Rule 保存名称、触发 Event 类型、结构化条件、紧急/重要/普通/静默优先级、确认要求和状态。
- Record 保存同范围 `trigger_event_id`、规则、优先级、安全审计引用和准备结果。
- Record 的 `delivery_status` 固定 `not_delivered`，`model_call_status` 固定 `not_performed`；不保存提示正文或模型响应。
- 内部准备 Event 不允许再次作为提示触发，避免形成无消费者约束下的递归回路。

### TokenBudget / TokenUsageRecord

- 每个用户/主体最多一个 TokenBudget，保存每日限额、会话限额、超额策略和状态。
- TokenUsageRecord 保存预算会话、可选同用户 Model、输入/输出/总 Token、发生/记录时间。
- `total_tokens` 必须等于输入与输出之和；来源固定 `explicit_api_input`，平台调用状态固定未执行，计费状态固定未计费。
- 预算检查按 UTC 日与 `budget_session_id` 聚合，检查本身不写入使用记录。

### AssistantBackgroundPolicy

- 每个用户/主体最多一条，保存 `idle|active`、后台开关、每小时 Wake/提示上限、允许的 Wake 类型和可选安静时段。
- `active` 不能与后台关闭同时存在；当前字段只参与准备资格，不启动调度器或驻留进程。

### 安全与事件关系

- Wake、提示规则和 Token Budget 以各自 ID 作为 `proactive_interaction` Permission 资源。
- 需要确认的提示与 Token 超额把最低风险抬高为 `high`，必须经过逐次 Confirmation。
- 六类 Event 只保存对象 ID、状态、分类和固定未执行标记，不保存音频、提示正文、模型响应或秘密。

## 对象关系摘要

- `User 1:N Subject`：一个用户可以拥有多个 AI 主体。
- `Subject 1:N SubjectState`：状态按版本保存，一个主体只有一个当前版本。
- `Subject 1:N Memory`：记忆严格按主体隔离。
- `User/Subject 1:N Event`：用户级事件可以不绑定主体，主体级事件必须双重归属。
- `Subject 1:N Conversation`：每个对话只属于一个主体。
- `Conversation 1:N Message`：会话使用 `sequence_number` 保存当前线性消息顺序。
- `Message 1:N MessageVersion`：版本通过单调版本号和同消息父版本形成当前线性版本链。
- `User/Subject 1:N Permission`：权限按用户、主体、目标、动作、范围和有效期判断。
- `User 1:N SecurityPolicy`、`User 1:1 UserSecurityPreferences`：安全配置按用户隔离并只能收紧权限。
- `User/Subject/SecurityPolicy 1:N SecurityPolicySessionGrant`：短时授权绑定策略版本和精确作用域。
- `User/Subject/Permission/SecurityPolicy 1:N Confirmation`：确认绑定一次具体权限/策略快照和操作作用域。
- `User/Subject 1:N AuditLog`：审计按用户隔离并可选绑定主体；Confirmation 可被审计引用。
- `User 1:N Device`、`Subject N:M Device`：设备归用户所有，主体通过明确授权使用。
- `Subject 1:N PrivateDomain`：私域正文严格按主体隔离。
- `User/Subject 1:N LifeFinancialRecord/LifeBudget/LifeCalendarEntry/LifeBodyRecord/LocalMemory`：生活数据属于 User Space，并按主体复合隔离。
- `User 1:N APIProvider`、`Subject N:M APIProvider`：服务配置归用户所有，按主体范围开放。
- `APIProvider 1:N Model`：模型目录项属于单一 Provider，并继承用户归属。
- `User 1:N ModelRoutingRule`、`Model 1:N ModelRoutingRule`：规则按用户/任务唯一，分别引用默认和可选备用模型。
- `Event`、`Memory`、`SubjectState` 和 `MessageVersion` 通过来源引用互相追溯，不复制秘密或大段原文。

完整关系图见 [`数据关系图.md`](数据关系图.md)。

## 逻辑唯一性与查询要求

以下是未来物理设计需要满足的逻辑要求，不代表已创建索引：

- 登录来源与外部身份组合在有效用户中唯一。
- `subject_id` 必须与 `owner_user_id` 的归属关系一致。
- 同一主体只能有一个当前 `SubjectState`。
- 当前物理子集要求同一对话的消息序号唯一、同一逻辑消息的版本号唯一；未来分支加入后还需扩展 branch 维度。
- 事件能够按用户、主体、类型和发生时间检索。
- 权限能够按用户、主体、目标、动作和当前有效状态检索。
- 确认能够按用户和 ID 精确读取，并原子决定及单次消费。
- 审计能够按用户、主体、操作类型、资源、风险、结果和时间检索。
- 外部设备标识在同一用户和适配器范围内唯一。
- API 服务配置的备用关系不能形成无限循环。
- 当前模型路由规则按用户/任务唯一，默认与备用模型必须同用户、具备任务能力且不能相同。
- 私域目录查询不能读取未授权正文。

## 导出、恢复与删除要求

- 导出需要保留对象标识、用户/主体归属、时间、版本、来源和关系。
- 脱敏导出不得包含 `secret_ref` 指向的秘密值、验证码、密码或设备凭据。
- 恢复必须先验证目标用户和主体，不能重新绑定到其他租户。
- 删除用户需要覆盖其主体、状态、记忆、会话、权限、私域和用户级配置，同时遵守审计保留政策。
- 删除主体需要覆盖主体级状态、记忆、会话和私域，但只撤销其对共享设备和 API 配置的关系。
- 删除会话及消息不自动删除主体状态、长期记忆或独立软件事件。

## 正式数据库物理设计前置决策

开发期 SQLite 已按迁移脚本实现当前基础子集；在建立正式数据库、生产物理模型和生产迁移前，仍需通过 ADR 确定：

1. 数据库产品和事务能力
2. 主键生成策略和物理字段类型
3. 结构化配置、正文和附件的存储方式
4. 多对多关系的物理建模方式
5. 加密字段、密钥引用和脱敏实现
6. 版本并发控制与唯一约束
7. 索引、分区、保留期限和清理任务
8. 备份、恢复、迁移和审计保留方案

这些决策未完成前，不把开发期 SQLite 子集视为正式数据库，也不创建面向生产的物理表结构或迁移方案。
