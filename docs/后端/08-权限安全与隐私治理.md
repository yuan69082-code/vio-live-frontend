# 08｜权限、安全与隐私治理

## 状态

- 文档状态：初始规划
- 权限连续层仅有规划所述基础框架状态
- 真实账号、Tool 和设备授权：未连接
- 正式上线前需要安全、隐私和法律审查

## 权限五档

| 档位 | 含义 |
| --- | --- |
| 始终允许 | 在指定主体、能力和范围内直接使用，不重复询问 |
| 本次会话允许 | 当前会话内有效，会话结束后失效 |
| 每次询问 | 每次执行前要求明确确认 |
| 禁止 | 不允许执行，但 AI 可以提出申请 |
| 禁止询问 | AI 不能执行，也不能再次申请 |

## 权限粒度

权限不能只做一个总开关，应按以下维度分别表达：

- 用户与智能体主体
- Tool、设备或外部服务
- 数据类型
- 具体动作
- 允许范围
- 有效时间
- 是否可以主动申请

## 授权和撤销

- 确认界面可以提供“记住我的选择，以后不再询问”。
- 长期授权显示主体、能力、范围、开始时间和撤销入口。
- 用户可随时撤销授权。
- 撤销后相关调用立即停止，不等待下一次登录。
- 授权、拒绝和撤销均需要访问记录。

## 操作确认

不可逆或高风险操作即使已有权限，也应说明本次具体内容和后果。这属于操作确认，不是重复申请权限。

需要单独确认的规划类别包括：

- 摄像头和门锁
- 付款和资金能力
- 身份证等身份信息
- 健康数据
- 亲密设备
- 删除数据、账号或主体

## 敏感信息边界

- API Key、密码、验证码、付款密码和完整证件号码不进入模型上下文。
- 事件和日志只保存必要的脱敏摘要。
- 穿戴、体重、生理期、亲密、财务和 AI 私域数据按敏感数据处理。
- 中转站和第三方服务必须说明数据去向。
- 用户只能在明确授权范围内连接外部能力。

## AI 安全边界

- AI 输出可能出错。
- 医疗、法律、付款、门锁、摄像头和设备控制等重要事项不能只依赖 AI。
- AI 的建议、权限申请和实际执行是三个不同阶段。
- 平台最低安全规则不能被主体设定、长期要求或用户角色描述绕过。
- 第一版不允许 AI 无限制自动执行。

## 数据权利

用户对与自己有关的数据拥有规划中的查看、纠正、撤销、导出、删除和停用权。隐藏版本、AI 私域和审计记录仍需遵守保留与删除政策，不能形成永久不可见数据。

## 上线前验收方向

- 每项真实能力均能识别权限档位和范围。
- 会话授权能在会话结束后失效。
- 长期授权可查询和撤销。
- 高风险操作不会因已有权限而跳过具体确认。
- 密钥和敏感原文不会进入模型、事件、日志或 GitHub。
- 跨用户和跨主体权限绕过测试全部通过。
