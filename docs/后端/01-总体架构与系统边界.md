# 01｜总体架构与系统边界

## 状态

- 文档状态：持续维护
- 实现状态：R0-A 合同、R0-B 状态装配与只读接口、R0-C 设置页读取及 R0 整阶段均已验收并推送；R2 与 R1 均已于 2026-09-05 正式验收通过；R3 尚未开始
- 依据：保留 v2.4 历史来源，现按 2026-09-04 四项决定修订版监工规划及 [ADR-034](../决策记录.md#adr-034) 执行；R0 后先 R2 再 R1，随后 R3 至 R13

## 目标

平台后端为 Vio Live 提供账号、数据、模型、权限、事件、设备和扩展能力的运行基础。即使前端只显示简单页面，后端也应能够保存用户与智能体的归属、重要变化、未完成事项、当前权限和可用能力。

## 自有层与可选外部系统

### 用户端前端

负责页面展示和用户操作，不直接承担数据库、密钥、模型路由、设备适配或审计职责。

当前前端通过独立 `src/api/` 和同源代理连接平台后端；F1 已接固定 V5 对话，R0-C 已接通用只读状态，R2 个人访问、首次设置、资料、多助手、能力配置与账户删除页已接真实个人 API，R1“对话”页已接个人独立聊天 API；其余尚未实施模块仍可能是演示或 mock。保留六个导航；R8 只验收公共机制和截至 R7 已完成模块，R9—R11 对应功能各自在本阶段完成前后端真实联调，R13 全量复验。当前接线不等于 R3 多会话或完整产品已完成。

平台后端保存助手长期设定、会话消息与不可变版本、带来源摘要以及开发调用方提交的 legacy/unverified 状态。单独保存这些记录不证明模型执行；现有固定 V5/F1 与首次 S4-Live 另有真实回复证据。R1 已收口个人生产入口的 legacy `state_update` 写入并保留历史来源，未把旧记录变成外部主体状态权威；Vio 仍拥有自己的账号、助手设定、会话、平台事件和生活等业务事实。Engine 专用链路中其 SubjectState 唯一权威不变。

每个 User 具有唯一 User Space。R2 已新增稳定 `personal_owner` 身份、受控初始化与服务端会话；历史 `development_unverified` 身份继续隔离，不会自动认领。User Space 保存空间状态和当前助手指针，首个助手可成为当前助手，后续切换只改变该指针，不修改或合并任何助手数据。统一数据隔离层按预定义资源类型先执行用户/助手/资源复合归属查询；私域、设备和生活资源命中后仍必须经过 Permission 与 Security Policy。

唯一 User Space 不限制助手数量。R2 已验收同一真实用户创建、查看、修改、选择和普通切换多个助手；R3 才完成各助手的多个会话及恢复、隔离。设定、消息版本、记忆、上下文、私域和调用归属不得因助手切换而串用；R3 相关产品能力尚未验收，也不扩展到助手市场或多助手协作。

现有 Engine 适配器的 v1.1 将 User Private Data、AI Private Space 和 Shared Space 分域，其“绑定主体引擎决定私域创建/编辑、Vio 验证并安全存储”的专用规则保留，不改成 Vio 拥有外部主体状态权威。它不定义独立 Vio 必须安装 Engine：Vio 自有记忆、上下文和私域产品职责分别按原阶段完成，完整私域在 R10 验收，不能通过本文宣称已实现。当前私域仍仅有五类显式输入与不可变版本基础，正文不自动进入通用 Context，读取经过 `private_domain` Permission → Security Policy → Confirmation；三域跨系统读写当时不参加第一轮最小连接测试。

生活管理属于 User Space，按用户与主体保存财务/预算、月历、身体和本地记忆。敏感访问必须通过 `life_data` Permission → Security Policy → Confirmation；统计只读取本地显式记录，不连接支付、银行、健康设备或模型。本地记忆只有用户明确标记后进入独立投影，不自动并入通用 Context。

数据导出层使用版本化 Schema 明确十二类范围、归属、必需字段和关系；先形成不含正文的预检记录，再以精确 `data_export:export` Permission 进入高风险安全确认。当前只保存计数、完整性与审计引用，`ready` 不生成文件或下载，不连接外部存储、机器人或其他载体，也不执行迁移。

模型配置层保存 Provider、Model 和按用户/任务唯一的默认/备用规则。Router 只返回确定性本地选择结果，不读取或修改 Context、SubjectState、Assistant Global Settings，也不发送网络请求或产生 Token。

### 平台后端

负责：

- 账号与身份确认
- 数据库存储与隔离
- 软件事件总线
- 对话版本和隐藏记录
- 模型与 API 路由
- Vio 自有上下文装配、折叠、跨窗口读取与本地记忆
- 权限、安全和访问日志
- MCP、Skill、插件和 Tool 管理
- 手机、家电与穿戴设备适配
- AI 私域与生活模块的数据服务
- 数据导出、备份、恢复和迁移
- 经选定适配器向可选外部主体运行时提供经过归属、Permission 和 Security Policy 筛选的平台事实
- 保存外部主体运行时明确返回的受控投影、缓存与审计事实，但不把它们变成 Vio Core 自创的运行时状态

### 可选外部主体运行时

外部主体运行时负责其所声明的主体连续性、主体表达和状态投影能力。它不是 Vio Core 的启动条件；`none` 模式是正式合法状态。Continuity Engine 是现有可选适配器之一：仅在启用该适配器时，它是其 `SubjectState`、revision、内部 Event、StateMutation 与 Evolution 的唯一权威，Vio 只能接收受控投影。第三方运行时必须通过独立适配器接入，不能把 Continuity Engine 专用机器合同冒充 Vio Core 合同。

### AI 模型

作为可替换的能力提供方。智能体主体状态不能因更换 GPT、Claude、GLM、本地模型或中转服务而丢失。

### 外部能力

包括 MCP、Skill、插件、Tool、手机、家电、穿戴设备和第三方服务。外部能力必须经过平台后端的连接、授权、调用和记录流程。

## 平台后端与相邻系统的边界

| 相邻系统 | 平台后端负责 | 平台后端不负责 |
| --- | --- | --- |
| 前端 | 提供受控数据和操作入口 | 页面布局、动画和视觉主题 |
| 可选外部主体运行时 | 通过 `Subject Runtime Port v1` 选择 `none` 或 `external`；只接收适配器声明的结果和投影 | 把外部运行时设为 Vio 启动条件；伪造外部能力、revision、表达或状态 |
| Continuity Engine 适配器 | 在既有专用合同中传递 SubjectBinding、PlatformObservation、CapabilityRequest/Result，并接收 Engine 结果 | 把 `continuity-integration/v1.1`、`continuity-capability/v1` 或 Engine 操作名定义为 Vio Core 通用合同 |
| AI 模型 | 路由、配置、自有 Context/记忆与 Token/权限安全通道；按已选模式处理候选和最终回复 | 模型自身训练/内部推理；伪造外部运行时状态或绕过其专用最终表达边界 |
| 外部能力 | 适配、授权、调用和日志 | 假装支持未接入的品牌或服务 |
| GitHub | 保存代码和规划文档 | 保存运行数据、用户数据和密钥 |

两种模式以 [Subject Runtime Port 说明](../../backend/docs/SUBJECT_RUNTIME_PORT_V1.md#mode-semantics) 为既有规则对应入口：独立模式由 Vio 模型链形成普通回复，外部模式只使用经过校验的运行时表达与投影；Vio 始终保有权限、安全、费用和真实执行权。R1 已完成真实个人身份和当前助手范围的独立路径；外部运行时选择、连接和真实联调仍须另行授权。未经用户另行要求重连，施工、测试与发布不探测、读取、启动或修改真实引擎；通用接口必须验证，具体外部系统另行接入，不作为 Vio 发布条件。

## 第一版必须覆盖

- 账号、数据库以及用户和智能体隔离
- 软件事件总线
- 消息编辑、重生成、删除和重置的版本记录
- 上下文摘要、跨窗口和本地记忆基础
- 模型/API 路由基础和手动选择
- 权限五档、撤销和访问日志
- AI 私域基础和数据导出
- 至少一个可验证的 MCP 或 Tool 闭环

## 暂缓范围

- 一次接完全部品牌家电
- 无限后台扫描和无限 Token
- 复杂多用户协作分支编辑
- 完整自主学习与自动永久人格变化
- 大量动画和高级主题市场
- 完整自动费用优化
- AI 无限制自动执行
- 真实转账、代扣和账户冻结
- 插件商店与商业分成

## 完成判断

平台后端完成不能以“已有本地原型”或“前端已有页面”为依据。正式完成至少需要真实账号隔离、数据库、事件、权限、模型路由、密钥保护、错误与访问记录，以及可被手机前端安全调用的稳定接口。

历史适配器验收：S2/S3 已证明正常、错误、崩溃和重启恢复；随后 S4、V5、F1 及 2026-08-14 首次 S4-Live 也已完成。后者只证明固定可销毁身份下的一次真实供应商链路，不证明真实登录、多助手产品能力、独立聊天、多租户、通用 Binding 或部署完成。专用合同见 [v1.1](14-continuity-engine连接契约v1.1.md)、接受证据见 [14c](14c-Engine-Contract-Final-Read-Only-Short-Confirmation-v1.md)、首次真实验收见 [后端开发日志](../../backend/docs/开发日志.md)。不能把历史共享验收重列为每次 Vio 发布前的真实引擎前置条件。

R0-A/B/C 的实现与历史证据见 [R0 矩阵](../../backend/docs/SUBJECT_RUNTIME_PORT_V1.md#r0-evidence)。历史 R0 文档收尾轮只核对文档与引用、未运行代码回归；随后 R0 已完成整体验收，R2 也已于 2026-09-05 正式验收通过。R1 现有独立聊天实现与页面闭环不等于 R3 多会话或完整产品可用；原真实功能、安全墙、权限、撤销、暂停、紧急停止及审计要求均保留。
