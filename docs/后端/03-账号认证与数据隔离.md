# 03｜账号认证与数据隔离

## 状态

- 文档状态：持续维护
- 实现状态：R2 已实现唯一个人所有者的受控初始化、服务端会话、退出/撤销、首次设置、资料和同一所有者多个助手；正式业务装配使用已验证会话，敏感资源继续接入 Permission 与 Security Policy
- 当前状态：R2 已于 2026-09-05 正式验收通过；邮箱、Google 和公开注册按个人自用决定继续暂缓，HTTPS/远程部署、多租户未完成。账户整体删除政策已确认并完成本机验证及页面联调；`x-vio-user-id` 只存在于历史开发合同和显式 test-support，不能作为生产授权依据

## 目标

为每个用户建立可验证身份，并保证用户、智能体、记忆、设备、密钥和私域数据不会相互串用。

## 第一版身份入口

- Google 登录
- 邮箱验证码登录或注册

GitHub 等账号绑定属于“我的”和连接中心的后续身份入口，不作为当前登录页必须完成的认证方式。

## 核心标识

### user_id

- 唯一标识一个平台用户。
- 所有用户级配置、登录身份和数据权利关联此标识。

### subject_id

- 唯一标识一个智能体主体。
- 主体必须有明确归属，不能脱离用户或授权范围被读取。
- 同一用户可拥有或切换不同主体，但数据不得自动混合。

### user_space_id

- 唯一标识一个用户的数据空间根，与 `user_id` 一对一。
- 只保存空间状态、开发期身份模式和当前助手指针，不保存或合并助手正文。
- 当前助手必须属于相同用户；切换只改变指针，不改变主体 ID 或任何主体级数据归属。

## 当前实现

- User 与 User Space 在同一事务创建；迁移 `015` 为既有用户回填空间。
- 既有用户按最早活动 Subject 稳定选择当前助手；新用户的首个 Subject 在指针为空时自动成为当前助手。
- 支持读取 User Space、助手列表、当前助手，以及切换至本用户的活动助手。
- Assistant Global Settings、Assistant Private Space 与 SubjectState 继续使用各自独立表和 `user_id + assistant_id` 复合归属；切换当前助手不复制、不重写、不合并数据。
- 数据隔离层覆盖用户数据、AI 数据、设备数据、生活数据和事件数据。资源只通过预定义查询类型访问，不接受任意表名、SQL 或过滤表达式。
- 所有权检查在数据库查询中带齐用户、助手和资源标识；组合不匹配统一返回未找到，不先暴露资源存在性。
- AI Private Space、Device 与生活数据只有在所有权命中后才进入 Permission → Security Policy → Confirmation；通过也只表示准备完成，不执行外部操作。

## 个人所有者会话与历史开发上下文

- 本机管理员通过 `initialize:personal` 在仓库外私有路径生成 15 分钟一次性邀请；第一个 HTTP 访客不会自动成为所有者。
- 口令验证后建立 HttpOnly、SameSite=Strict 会话；绝对期限 30 天、闲置期限 7 天。写请求还校验 CSRF 与同源，支持退出、目标会话撤销、访问审计和异常登录提示。
- 正式个人身份使用随机服务端 ID，不认领旧固定 Profile、数据库第一位用户或旧 `development_unverified` 数据。旧无归属缓存保留隔离，不自动重发、迁入或删除。
- 同一所有者可创建多个助手。名称、头像和设置保存于对应对象；当前助手是用户级选择，切换不迁移、合并或重归属历史数据。R3 的每助手多会话和 R1 独立聊天尚未实施。

以下 `x-vio-user-id` 说明只描述历史开发 API；生产个人装配已在路由前使用验证会话，并拒绝前端用该头伪造身份：

- `GET /api/v1/users/current` 要求调用方提供 `x-vio-user-id`。
- 服务只按该 ID 查询明确用户，不默认选择数据库中的第一位、最新或唯一用户。
- 该请求头与 URL 中的 `userId` 一样，只是开发期请求范围，不证明调用者身份，也不授予任何资源权限。
- test-support 可为历史领域测试显式注入访问替代，但生产没有环境开关或 Header 后门。
- 当前个人会话不等于公开认证或可直接部署；非 loopback 必须另行完成 HTTPS、运维和部署安全。

## 账号与主体关系

### R2 账户整体删除与受限恢复

- 本人完成既有账户级高风险确认后，持久化 7 天删除等待任务；立即撤销旧普通会话、停止所有者业务及凭据使用，不伪造助手作为授权主体。
- 删除专用 Cookie/验证只能查询绑定任务、在截止前验证口令撤销，或在到期后请求一次受控重试；不能读取资料、消息、凭据或其他业务。撤销后须正常登录建立新会话，不恢复旧会话或已撤销的凭据/权限。
- 到期按实际所有者数据行与依赖清单执行限定删除事务；失败、停服和文件占用保持待处理/失败，不按日历直接显示已删除。普通业务对不可变历史的更新/删除保护保持生效。
- 实际删除后最小凭据保留 30 天，受管备份对应数据最迟 14 天处理；恢复前应用删除标记。不管理用户自行保存副本，不宣称 SSD 物理擦除。没有登记受管副本时报告 0，不冒称完整备份能力。
- 本项为 R2 整个所有者空间的删除，不开放 R3 单消息删除、R10 单私域删除或 R11 完整备份产品。精确接口和状态只以 [R2 个人合同](../../backend/docs/R2_PERSONAL_CONTRACT.md) 为准；历史政策未决记录保留，当前政策不再是阻塞。

### 归属不变量

- 登录确认用户身份后，再确定当前主体。
- 首次设置创建或选择主体，并建立归属关系。
- 主体的全局设定、连续状态、记忆、私域和设备授权独立保存。
- 更换模型或外观不改变主体标识。

## 数据隔离要求

- User Space 按 `user_id + space_id` 隔离，并通过复合外键保证当前助手属于同一用户。
- Assistant Global Settings、Assistant Private Space 和 SubjectState 分别存储，不能通过“当前助手”指针形成级联覆盖或跨助手合并。
- 会话与消息按用户和主体隔离。
- 当前 Conversation、Message 与 MessageVersion 的所有查询/写入都同时限定 `user_id`、`subject_id`、`conversation_id`，消息级继续限定 `message_id`；错误组合统一按未找到处理。
- 连续状态、记忆和时间线按主体隔离。
- API Key 按用户独立配置并加密保存。
- 设备按账号和主体授权，其他用户不可见、不可控。
- AI 私域按 `user_id + assistant_id + space_id` 保存于专用表；其他用户、主体或 Space 组合按未找到处理。正文读取还必须通过精确 `private_domain` Permission 与 Security Policy。
- 生活数据按 `user_id + subject_id` 保存于财务、预算、月历、身体和本地记忆专用表；读取与修改还必须通过主体范围的精确 `life_data` Permission 与 Security Policy。
- 管账、健康、生理期和亲密记录不能跨用户或跨主体读取。

### 当前五类访问规则

| 数据类别 | 归属标识 | 基础访问规则 |
| --- | --- | --- |
| 用户数据 | `user_id + user_space_id` | 所有权复合查询；开发期身份不等于认证 |
| AI 数据 | `user_id + assistant_id + resource_id`，状态另带引擎 `subject_id` binding | 普通设定/状态投影先验证复合归属；私域再经过权限与安全策略；状态权威仍在引擎 |
| 设备数据 | `owner_user_id + device_id`，操作带 `assistant_id` | 归属命中后检查精确 Device Permission 与 Security Policy |
| 生活数据 | `user_id + subject_id + record_id` | 归属命中后映射到四个固定 `life_data` 安全范围 |
| 事件数据 | `user_id + event_id`，可选 `subject_id` | 用户范围查询；提供主体时必须同时匹配 |

## 外部服务授权

- Google、Gmail、GitHub、MCP、API、手机和家电分别授权。
- 登录身份不自动等于外部服务授权。
- 每项授权需要保存来源、范围、主体、开始时间和撤销状态。
- 用户撤销外部连接后，平台不得继续调用该能力。

## 会话与风险边界

- 登录会话和工具/设备授权是不同层级，不应互相替代。
- 高风险操作即使处于登录状态，也需要遵循权限档位和操作确认。
- 密码、验证码、付款密码和完整证件号码不得进入模型上下文或软件事件正文。
- 恶意账号和危险能力可被限制、暂停或封禁，正式规则需在上线前完成法律与安全审查。

## 公开测试前完成标准

- 真实登录身份能够稳定映射到唯一用户。
- 主体归属可验证且不可越权修改。
- 用户、主体、设备、密钥和私域数据均有隔离测试。
- 数据导出和删除只作用于正确用户和正确主体。
- 少量并发用户使用时不得出现串数据。

当前开发期已经覆盖 User Space 回填、当前助手持久化、跨用户助手切换拒绝、Global Settings/SubjectState 跨助手隔离，以及用户/AI/设备/生活/Event 资源的复合归属测试。真实身份认证、生产数据库行级安全、并发与数据删除/导出隔离仍是公开测试前任务。
