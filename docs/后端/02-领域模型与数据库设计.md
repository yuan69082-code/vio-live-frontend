# 02｜领域模型与数据库设计

## 状态

- 文档状态：第二阶段逻辑模型已细化
- 实现状态：已用开发期 SQLite 实现账号/隔离、设定/私域、对话/摘要/状态、Event、模型路由、扩展/设备/生活、Wake/主动提示/Token/后台策略，以及 Permission/SecurityPolicy/Confirmation/AuditLog 子集和迁移记录
- 当前限制：其余逻辑对象、事件消费、真实模型调用、正式数据库、生产迁移、加密和备份尚未实现

## 设计目标

在编写后端代码前，先明确每类数据属于谁、与哪个智能体相关、从哪里产生、何时产生、谁能读取，以及如何导出和删除。

## 第二阶段详细设计

- [数据库设计.md](数据库设计.md)：核心对象、字段语义、数据分类、约束与生命周期
- [数据关系图.md](数据关系图.md)：对象关系、数据归属、消息版本、事件数据流与删除影响

两份详细文档仍是数据库产品无关的逻辑基线。当前还将 WakeRule、ProactivePromptRule/Record、TokenBudget/Usage 与 AssistantBackgroundPolicy 映射到开发期 SQLite；这些对象只保存配置、显式计量和未执行准备，不代表真实语音、模型或后台运行。通用、私域与本地记忆 Context 都是受不同边界约束的临时投影，SensitiveData 仅为分类元数据。

## 核心数据对象

### 用户账号

- 使用唯一 `user_id` 表示平台用户。
- 保存账号身份、登录方式和用户级设置的归属关系。
- 不在 GitHub 或前端代码中保存凭据。

### 智能体主体

- 使用唯一 `subject_id` 表示一个智能体主体。
- 主体归属于用户；团队归属只保留模型边界，复杂协作暂缓。
- 名字、性格、人设和长期要求属于主体级长期设定。
- 当前物理结构保持名称/头像在 Subject，其他长期设定在一对一 `assistant_global_settings`；动态 SubjectState 单独保存且不会被设定更新覆盖。

### 会话、消息与版本

- 会话关联用户和主体。
- 消息需要区分用户消息、AI 回复、时间和当前可见版本。
- 编辑、重生成、删除、分支和窗口重置需要保留受控版本记录。
- 当前物理子集已拆分稳定 Message 与不可变 MessageVersion，支持线性文本、用户编辑和主体回复重生成记录；删除、分支、重置、附件和模型生成仍未实现。

### 软件事件

- 记录外观、权限、能力、生活模块、设备和数据变化。
- 事件保存类型、时间、来源、主体、摘要和可见范围。
- 秘密密钥、付款密码和完整证件号码不进入事件正文。
- 当前物理子集提供五种原有基础事件和四种对话结构事件、创建与查询；能力/数据变化的独立事件名、消费流程和可见范围策略仍待后续阶段实现。

### 摘要、记忆与来源

- 摘要可包含事件重点、未完成事项、情绪、认知、想法与来源引用。
- 长期记忆保存来源、时间、关联主体、权限和是否参与上下文。
- 原始内容、摘要和引用关系需要能够区分。
- 当前物理子集已实现不可变 ConversationSummary、MessageVersion/Event 来源和跨窗口最新摘要读取；摘要内容由开发调用方提交，Memory 尚未实现。

### 权限与授权

- 权限按主体、能力、数据类型、动作、范围和有效期保存。
- 区分长期授权、会话授权、每次确认、禁止和禁止询问。
- 撤销和风险确认需要留下可追溯记录。
- 当前 Permission 物理子集使用五档名称，按用户、主体、资源实例和操作精确判断；Permission 自身仍没有会话档位。独立 Security Policy 已实现确认后 30 分钟的精确 `session_allow`，但尚未与正式认证会话结束联动。

### 安全、确认与审计

- Security 按 Permission、风险等级和确认要求编排，只返回执行资格，不执行资源。
- 风险分为 `low`、`medium`、`high`、`critical`；平台最低要求不能被用户偏好降低。
- Confirmation 支持无需确认、每次确认和用户自定义确认；持久记录绑定完整资源作用域、Permission/Policy 快照、开发期安全会话和风险说明，批准后只能消费一次。
- AuditLog 独立于 Event，只追加用户、可选主体、操作、资源引用、风险、结果、确认引用和时间，没有任意 payload 或正文字段；资源引用必须使用平台不透明 ID。
- SensitiveData 模块只定义 API Key、身份、支付、私密记录和 AI 私域五类元数据并提供只读分类查询，不建立敏感实例表；这不等于整个平台没有账号邮箱等身份字段。

### 扩展与调用记录

- 模型/API、MCP、Skill、插件和 Tool 分别保存配置状态与适用范围。
- 实际调用保存时间、主体、能力、权限结果和执行结果摘要。
- 密钥只保存在服务器密钥库或设备安全存储。
- 当前已实现 APIProvider、Model 目录、八类能力标签和六类任务默认/备用 ModelRoutingRule；Router 只选择本地配置，不保存 Key、不连接服务，也没有实际调用记录。

### 设备

- 设备按账号和主体授权。
- 保存设备类别、位置、状态、适配器、允许动作和授权状态。
- 摄像头、门锁和亲密设备需要独立的访问与危险操作记录。

### AI 私域

- 当前按用户与助手保存唯一 Space，正文与 User Space 使用独立表。
- AI 状态、认知、长期偏好、工作记录和私有笔记只接受显式输入并按不可变版本追加。
- 读取、写入、状态、Context 投影和导出准备复用 `private_domain` Permission 与 Security Policy。
- 查看申请、部分开放、删除和真实导出仍未实现；用户的数据权利不因正文受限而消失。

### 生活管理数据

- 当前使用专用表保存管账记录/预算、四类月历、身体指标/目标和本地记忆。
- 所有记录绑定 `user_id + subject_id`，属于 User Space；本地记忆不等同于完整通用 Memory。
- 使用 `life_data` 的 `finance`、`calendar`、`body`、`local-memory` 固定资源范围经过 Permission 与 Security Policy。
- 金额以最小货币单位整数保存；趋势为确定性差值，AI 建议只保存显式输入。
- 财务、健康、生理期和亲密记录按敏感数据处理。
- 第一版不保存或执行付款密码、真实转账、代扣或账户冻结命令。

## 通用归属信息

所有需要持久化的业务数据，应能表达以下关系：

- 所属用户
- 所属智能体主体
- 数据来源
- 创建与更新时间
- 当前版本或状态
- 可见范围和权限
- 与事件、会话、消息或设备的关联
- 保留、导出和删除状态

## 隔离原则

- 禁止跨用户读取或修改数据。
- 禁止跨主体读取连续状态、记忆、私域和设备授权。
- 外部服务返回的数据仍需重新绑定用户、主体、来源和权限。
- 本地 JSON 只适合单人原型；公开测试前必须迁移到隔离数据库。

## 数据生命周期

- 支持创建、更新、版本记录、导出、备份、恢复和删除。
- 隐藏版本仍受保留周期和用户删除权约束。
- 数据恢复必须保留来源、时间、版本和关系。
- 具体保留期限、数据库产品和存储方案等待后续 ADR 决定。
