# 11｜数据导出、备份与迁移

## 状态

- 文档状态：规划持续维护，跨模块 Export Schema 与导出准备基础已落地
- 实现状态：已实现三类版本化 Schema、十二类范围、完整性预检、安全准备、导出记录和未来载体未配置契约
- 当前限制：不返回业务正文、不生成文件/下载、不连接外部存储或机器人，不执行备份、恢复或迁移

## 目标

让用户能够理解、保存、恢复、删除和迁移与自己及其智能体有关的数据，并在未来更换设备、模型或载体时保留经历、状态和数据关系。

## 可导出范围

- 主体状态
- 原始软件事件
- 消息隐藏版本和重置记录
- 窗口摘要
- 完整对话
- AI 私域数据和开放记录
- 权限与访问记录
- 模型、工具和扩展配置状态
- 设备与授权数据
- 月历、管账、体重和本地记忆等生活模块数据

密钥、密码和不能安全迁移的秘密凭据不应以明文导出。

## 导出形式

规划至少提供：

- 人类可读格式
- 机器可迁移格式

导出内容应尽量保留时间、来源、版本、主体归属和数据关系。具体格式等待实现阶段确认。

AI Private Space 既有 Export Manifest 继续只预留 `json` 与 `human_readable` 格式，返回用户/助手/Space 范围和版本元数据，不包含正文。跨模块导出使用独立 `vio-live-export-v1` Schema，当前支持 `full`、`selected`、`migration` 三类；它不替代私域专用安全入口，也不会把私域正文复制到导出记录。

## 当前 Export Schema 与记录基础

当前 Schema 固定登记十二类范围：用户数据、SubjectState、Event、MessageVersion、ConversationSummary、Assistant Private Space、Assistant Global Settings、Permission、Security Policy、Tool、Device、Life Data。每类定义数据分类、用户/主体归属、敏感分类、必需字段和关系字段；Schema 版本与创建时间独立保存，后续版本不得原地覆盖。

导出准备分为两步：

1. 创建不含正文的导出记录，按 `user_id + subject_id` 复合范围统计数据，并检查必需字段与数据库外键。
2. 使用返回的 `exportId` 创建精确 `data_export:export` Permission，再进入 Security Policy 与高风险逐次 Confirmation。

导出记录保存请求用户、主体、创建时间、Schema 版本、导出类型、范围、敏感分类、每类/每表计数、缺失字段数量、归属/字段/外键结果、Permission 结果和 AuditLog 引用。`ready` 只表示未来生成资格；数据库把载荷、文件、外部存储和迁移状态分别固定为未生成、未创建、未连接、未执行。

## 导出范围选择

- 全量导出
- 按模块导出
- 脱敏导出
- 是否包含隐藏消息版本和重置记录

用户需要明确知道导出包含什么，以及哪些内容因安全原因被排除或脱敏。

## 备份与恢复

- 数据库需要支持备份和恢复。
- 恢复后仍需保持用户、主体、来源、时间和版本关系。
- 恢复操作需要形成数据变化事件和受控记录。
- 恢复不能把一个用户的数据写入另一个用户或主体。
- 具体备份周期和恢复目标等待部署规划确定。

## 删除与保留

- 支持删除账号。
- 支持删除单个智能体主体。
- 支持删除单条或单类生活、记忆和私域数据。
- 隐藏版本和审计记录仍受用户权利、保留周期和法律要求约束。
- 删除结果需要明确区分立即不可见、等待清理和依法保留等状态；具体规则等待正式隐私政策确定。

## 未来载体迁移

未来接入仿真机器人、实体设备或其他 AI 平台时，迁移对象不只是聊天文本，还包括：

- 主体经历
- 当前状态
- 时间关系
- 记忆来源
- 事件与版本关系
- 权限与可见性信息

本文件不定义具体机器人、设备或第三方 AI 平台协议。

当前仅提供 `robot` 与 `other_carrier` 两类未配置契约。契约声明可接受的 Schema 版本，但 `adapterStatus=not_implemented`、`connectionStatus=not_connected`、传输/恢复能力均为关闭。迁移准备只验证记录类型为 `migration`、状态为 `ready` 与 Schema 兼容；不接受服务地址、设备 ID、控制参数、凭据或业务数据，不建立连接或传输。未来真实迁移必须重新执行身份、归属、Permission、Security Policy 和 Confirmation，当前准备结果不能作为长期执行授权。

## 运行数据边界

- 运行数据不得自动写入 GitHub。
- 数据恢复不得修改项目仓库代码。
- API Key 和设备凭据不进入普通导出包。
- 管理者后台只能在授权范围内查看用户、状态、事件、错误和使用日志。

## 第一版验收方向

- 用户可以导出自身和指定主体的数据。
- 导出结果能表达来源、时间、版本和关系。
- 脱敏导出不会包含秘密值。
- 备份恢复不破坏用户和主体隔离。
- 删除账号和删除主体的范围清晰且可验证。

当前已满足版本化范围、归属/字段/关系检查、安全确认和导出记录基础；尚未满足真实数据包、人类可读文件、下载、加密、备份恢复、删除或载体迁移执行。
