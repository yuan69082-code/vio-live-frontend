## 测试范围

### 数据隔离

- 不同用户不能读取或修改彼此数据。
- 同一用户的不同主体不会混用状态、记忆、私域或设备权限。
- 每个用户只有一个 User Space；首个助手选择、当前助手切换和重启后指针必须稳定，且不能改变任何助手数据归属。
- 所有权检查必须先按固定 `user_id + assistant_id + resource_id` 复合条件查询；错配组合按未找到处理，高敏感资源命中后仍必须通过 Permission 与 Security Policy。
- AI Private Space 查询必须同时限定用户、助手和 Space；User Space 与私域使用独立表，错误组合不得泄露内容存在性。

### API 与前后端连接

- 所有 JSON 接口稳定返回 `success`、`data`、`error` 和 `timestamp`。
- User、Subject 与 Dashboard 接口保持用户归属隔离；Subject 更新与 `subject_updated` 事件原子提交。
- 前端开发服务器可以通过同源代理访问后端健康检查，后端不可达不会阻塞页面启动。
- 当前用户开发请求头不得被误认为登录认证；页面 mock 未经后续迁移不得删除。

### 对话与事件

- 当前实现必须验证 Conversation/Message 复合归属、稳定顺序、编辑/重生成父版本链、当前版本和陈旧写冲突。
- 删除、分支和重置仍是未来验收项，不能由当前线性父版本链冒充完成。
- 软件事件不包含秘密原文。
- 对话事件不得复制标题或消息正文；Event 失败必须回滚消息和版本写入。
- 窗口重置不自动删除连续状态。
- ConversationSummary 必须至少引用一个同范围 MessageVersion 或 Event，跨窗口读取必须排除当前 Conversation 且不能跨主体。
- 当前 SubjectState 必须保留历史、只存在一个当前指针，`state_update` 来源和未解决 Event 必须属于同一用户与主体；真实接入测试还必须确认 continuity-engine 唯一权威、engine revision/update ID 去重、乱序隔离和 Vio 只保存投影。
- Assistant Global Settings 必须与 Subject 一对一、按用户/主体隔离；七类字段更新、无变化语义、Event 原子性和重启持久化必须验证。
- Global Settings 更新不能创建、覆盖或切换 SubjectState；长期要求和禁止事项不能替代平台安全规则。
- Context 公共 API 必须按产品顺序投影已有平台事实，明确标记 Memory 未实现以及该端点未调用模型、外部 API、continuity-engine；在正式交互链路中最终认知 Context 只能由引擎组织。
- 摘要/来源和状态/未解决事件/当前指针任一写入失败时必须整体回滚。
- 连接层后续必须测试请求/Event/回复/状态幂等、Observation 无 StateMutation、引擎不可用/超时/断线、状态对账、前端不直连和跨用户/跨助手事实包隔离。

### 权限与安全

- 五档权限行为符合定义。
- 会话授权按时失效。
- 高风险操作需要具体确认。
- 撤销权限后调用停止。
- Permission 拒绝不能被确认绕过；长期允许不能跳过高风险确认。
- Security Policy 只能收紧 Permission；自动确认和 `session_allow` 不能跳过 `high` / `critical` 平台底线。
- `session_allow` 必须确认后建立，绑定用户、主体、策略版本、安全会话、资源、动作和风险，并按时失效。
- 策略/偏好变更、Permission 生命周期和确认请求必须产生对应最小审计或 Event。
- 确认不能跨用户、主体、资源、动作或权限版本复用，批准后只能消费一次。
- `allow_once` 在确认前不消费，安全链满足后才消费。
- 审计只保存最小字段，不保存秘密原文或任意请求正文。
- 私域 `read`、`write`、`manage`、`export` 必须经过 `private_domain` Permission 和高风险确认；Policy 拒绝时不得读取或写入正文。

### 模型与扩展

- 模型切换不影响主体状态。
- 六类任务的默认/备用规则必须保持用户归属与能力匹配，显式规则不可用时不得伪造成功。
- Provider/Model 测试状态不得被当作真实连接证明；Router 响应必须明确标记未执行模型与外部 API。
- API Key、Token 和 Secret 原值不得进入业务请求、SQLite、响应、日志或 Git；受限 secretRef 只能进入独立 credential binding，不能进入 Provider 公共投影或 Capability 外部 JSON。
- 打开应用不自动消耗 Token。
- Wake `voice` 规则不得被解释为麦克风或系统授权；启用必须有应用内授权，撤销后必须停用。
- 主动提示必须由同范围 Event 触发；静默优先级必须抑制投递，需要确认的规则不得绕过高风险逐次确认。
- Token Budget 必须分别限制 UTC 日与预算会话；阻止、延后和要求确认三种超额策略结果可验证。
- 旧显式 Token 使用记录必须保持平台未调用、未计费语义；V4 Provider 实际 usage 进入独立可信账本，预算检查本身仍不得写入用量或触发模型。
- 后台 `idle` / `active` 与限制只控制准备资格；当前不得启动调度器或驻留任务。
- 外部能力失败不会被伪造成成功。
- 推荐能力不会绕过执行权限。
- Registry 启用不得被解释为 MCP 已连接、Plugin 已安装或 Skill/Tool 可执行。
- Capability Permission 预览不得消费 `allow_once`，且跨用户、跨主体能力不得泄露。
- Tool 准备必须按 Permission 与 Security/Confirmation 处理并关联审计；当前执行状态必须保持 `not_executed`，不得接受真实执行载荷。

### 设备适配

- 七类 Device Registry 与四类 Device Capability 必须按用户隔离，品牌只决定未来 Adapter 类型，不表示已支持。
- 注册和启用不得被解释为物理连接或状态已读取；响应必须保持 `not_connected`、`not_observed`。
- 主体设备授权必须复用 Permission，且不能跨用户；操作准备必须经过 Permission、Security 与 Confirmation。
- 设备操作当前按极高风险每次确认；通过准备后仍必须保持 `not_executed`，不能接受控制参数或调用厂商 API。
- `device_changed`、DeviceOperationLog 与 AuditLog 必须只保存最小事实并保持事务一致，不得写入外部设备 ID、位置、凭据、实际状态或敏感参数。

### 数据治理

- 五类私域内容必须不可变追加并保留父版本，Event、AuditLog 和 Export Manifest 不得复制正文。
- 私域 Context 必须保持独立安全入口并明确零模型/外部/连续性调用；Export Manifest 当前不得生成文件。
- Export Schema 必须版本化并覆盖十二类稳定范围；导出范围与用户选择一致。
- 创建导出记录必须检查用户/主体归属、必需字段与外键，且记录不得复制业务正文。
- 导出准备必须使用精确 `data_export:export` Permission 并经过高风险逐次确认；`ready` 不得表示文件或迁移已完成。
- 机器人/其他载体契约必须保持未实现、未连接、未执行，不接受地址、凭据或业务数据。
- 备份恢复不破坏隔离关系。
- 删除账号、主体和单项数据的范围清晰。
