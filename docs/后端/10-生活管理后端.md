# 10｜生活管理后端

## 状态

- 文档状态：基础实现已落地，持续维护
- 实现状态：管账、预算、月历、身体管理、本地记忆、权限安全与事件闭环已完成
- 当前前端：月历、管账和体重/三围仍使用模拟数据，本阶段未修改前端 `src`
- 当前限制：不连接支付、银行、医疗服务、穿戴设备、真实模型、MCP 或第三方服务

## 数据归属与安全边界

- 所有生活记录同时关联 `user_id + subject_id`，属于 User Space，不属于 Assistant Private Space。
- 使用 `resourceType=life_data`，按主体固定划分 `finance`、`calendar`、`body`、`local-memory` 四个资源范围。
- 读取、写入和管理固定经过 Permission → Security Policy → Confirmation。
- 当前以 `sensitive_data_access + private_record` 分类，风险至少为 `high`，必须逐次确认。
- 任何生活记录都不会默认共享给其他主体、Tool、设备、模型或外部服务。

## 管账模块

已实现：

- 收入与支出记录、分类、金额、币种、发生时间和备注。
- 按类型、分类和时间范围查询。
- 按收支类型、分类和币种统计。
- 按 UTC 月份汇总收入、支出和净额。
- 按主体、月份、分类唯一保存预算，支持启停和阈值百分比提醒规则。

金额在数据库中使用最小货币单位整数保存，API 使用两位小数字符串，避免二进制浮点累计。当前预算不会触发提醒任务，月度汇总只读取显式保存记录；不连接银行、不读取账单、不执行支付。

## 月历模块

已实现四类记录：

- `anniversary`：纪念日。
- `menstrual_period`：生理期记录。
- `intimate_record`：亲密记录。
- `ordinary_event`：普通事件。

记录支持标题、开始/结束时间、备注、提醒规则、创建、查询和局部更新。提醒规则当前只保存启停与提醒时间，不运行调度器或发送通知。生理期和亲密记录属于高敏感用户数据。

## 身体管理模块

已实现：

- 体重、胸围、腰围、臀围及测量时间。
- 当前目标值、目标日期和备注。
- 按时间查询及各指标首尾确定性差值。
- `aiSuggestion` 存储字段。

`aiSuggestion` 仅保存调用方显式提交文本，不调用模型。趋势只是数学差值，不生成健康建议，不构成医疗诊断。当前不读取穿戴设备、训练服务或饮食服务。

## 本地记忆模块

已实现：

- 按用户与主体保存标题和正文。
- 查询与数量限制。
- `participatesInContext` 用户控制标记。
- `exportMarked` 用户导出选择标记。
- 独立、受控的本地记忆 Context 投影。

本地记忆存放于专用 User Space 表；只有明确标记 `participatesInContext=true` 的记录会进入独立投影。投影不会自动并入通用 Conversation Context，也不会调用模型或外部 API。`exportMarked` 当前不生成文件或传输数据。

## 软件事件

- `life_event_created`：财务记录、月历记录和本地记忆创建或标记变化。
- `budget_changed`：预算新增或更新。
- `health_record_updated`：身体指标或目标变化。

事件只保存模块、记录 ID 和变化类型，明确标记不包含敏感正文；不得复制金额、分类、身体数值、月历类型/标题、亲密内容、备注、记忆正文或建议文本。

## API 与执行边界

API 路径、参数和确认流程见 [`../../backend/docs/API.md`](../../backend/docs/API.md)。所有接口只执行本地 SQLite 数据操作。安全响应中的 `executionStatus=not_executed` 表示没有支付、设备、模型或第三方副作用；安全确认通过后的本地保存和查询会正常完成。

## 当前验收

- 收入/支出、预算、统计和月度汇总可保存、读取并在重启后保持。
- 四类月历及提醒规则可保存、查询和更新。
- 身体指标、目标和趋势可保存、查询且明确非诊断。
- 本地记忆可保存、查询、控制上下文参与和导出标记。
- 用户/主体隔离、Permission/Policy 拒绝、高风险确认、事件脱敏和外键完整性通过测试。

## 后续范围
