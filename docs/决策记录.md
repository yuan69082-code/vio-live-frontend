# Vio Live 决策记录

## ADR-001｜前端技术栈

- 日期：2026-07-22
- 状态：已采用
- 决策：使用 React + Vite + TypeScript 建立 Vio Live 前端项目。
- 原因：项目需要组件化页面结构、快速本地开发体验与明确的类型检查能力。

## ADR-002｜当前开发边界

- 日期：2026-07-22
- 状态：已采用
- 决策：当前阶段只开发前端页面，不连接后端、数据库或 API。
- 影响：登录页中的 Google 登录、邮箱验证码和登录/注册均只提供前端原型与本地演示反馈，不执行真实身份验证。

- 日期：2026-07-22

- 决策：按规划逐页开发并逐页审查，不提前开发后续页面。

## ADR-004｜首次设置原型的页面流与状态

- 日期：2026-07-22
- 状态：已采用
- 决策：登录页与首次设置页暂时使用 React 本地状态完成页面切换，不引入路由、持久化或外部服务。
- 原因：当前阶段只验证单用户首次设置体验，保持原型简单，并严格遵守不连接后端、数据库或 API 的开发边界。
- 影响：刷新页面会回到登录页，首次设置内容不会保存；待后续整体导航与数据方案确定后再调整。

## ADR-005｜主导航采用配置驱动的本地状态切换

- 日期：2026-07-22
- 状态：已采用
- 决策：六个主导航入口由统一配置数组生成，当前使用 React 本地状态切换占位页，不引入路由库。
- 原因：本阶段只建立手机端导航骨架，统一配置可以保证入口顺序、标签、图标和占位页保持一致，同时避免提前引入具体页面架构。
- 影响：导航切换不会产生真实 URL 或持久化状态；待具体页面与整体路由需求明确后再评估路由方案。

## ADR-006｜工作台采用展示组件与集中模拟数据

- 日期：2026-07-22
- 状态：已采用
- 决策：工作台页面拆分为关注卡片、今日概览、最近变化、快捷入口、通用输入框和共用图标组件；模拟内容集中放在独立数据文件中。
- 原因：页面模块较多，展示组件与数据分离可以保持第一屏清晰，也便于后续在不改变视觉组件的情况下替换真实数据来源。
- 影响：当前组件只消费本地模拟数据，不承担数据请求、持久化或业务执行。

## ADR-007｜工作台使用固定视口与内部滚动

- 日期：2026-07-22
- 状态：已采用
- 决策：主导航外框固定为当前视口高度，工作台顶部、通用输入框和底部导航保持固定，只有工作台主体内容独立滚动。
- 原因：手机端需要让通用输入和主导航随时可用，同时避免从较长的首次设置页进入后继承外层滚动位置。
- 影响：后续主导航页面需要明确自身内容滚动区域，不能依赖整个文档页面滚动。

## ADR-008｜对话页采用固定控制区与独立消息滚动

- 日期：2026-07-23
- 状态：已采用
- 决策：对话页顶部、模型与上下文控制、记忆/状态/工具入口及输入区保持固定，只有消息列表独立滚动；页面按展示职责拆分组件，并集中维护模拟数据。
- 原因：手机端长对话需要让会话信息、上下文状态、输入工具与主导航随时可用，同时避免页面级滚动造成输入区位置不稳定。
- 影响：当前各控件只提供本地界面状态，消息操作与发送不执行真实逻辑；后续接入真实能力时，应在不改变展示组件职责的前提下增加数据与命令层。

## ADR-009｜连续性信息采用类型化卡片与集中模拟快照

- 日期：2026-07-23
- 状态：已采用
- 决策：连续性页面将身份、关系、近期延续、时间节点和形成中的想法组织为统一类型的展示卡片，当前状态使用专用卡片；全部模拟内容集中在独立数据文件中，页面主体独立滚动。
- 原因：连续性信息类别多但展示结构稳定，统一数据结构可以降低重复组件数量，并让特殊状态视觉与普通信息卡片保持清晰边界。
- 影响：当前页面只渲染一次本地模拟快照，不进行真实记忆读取、写入、推断或状态持久化；未来接入数据层时应保持展示组件不直接依赖外部服务。

## ADR-010｜AI 私域申请采用确定性本地状态机

- 日期：2026-07-23
- 状态：已采用
- 决策：AI 私域目录与申请页使用 React 本地状态切换；每个模拟目录项目预设一种回复状态，由统一状态映射决定开放范围与展示文案。
- 原因：本阶段需要完整演示全部开放、部分开放、暂时拒绝和延后开放四种结果，同时必须避免产生任何真实 AI 判断、网络请求或持久化行为。
- 影响：同一目录项目每次都会返回固定模拟结果，返回目录后申请理由和回复状态会重置；未来接入真实审批能力时，应将判断与记录逻辑放在独立数据层，展示组件只消费明确结果。

## ADR-011｜能力中心采用统一分组壳与局部模拟状态

- 日期：2026-07-23
- 状态：已采用
- 决策：模型/API、MCP、Skill、插件、Tool 和设备使用统一能力分组壳承载标题、图标与状态摘要，各专用组件只管理自身的本地交互状态，静态能力信息集中在独立模拟数据文件中。
- 原因：六类能力展示字段不同，但层级和视觉结构一致；统一分组可以减少重复布局，同时让启停、连接测试和管理反馈保持在对应能力范围内。
- 影响：刷新或离开页面后所有模拟交互会重置，任何按钮和开关都不会产生网络、安装、授权、卸载或设备控制副作用；未来接入真实服务时，应在组件之外增加统一能力数据与命令层。

## ADR-012｜设备中心采用能力入口下的两层本地视图

- 日期：2026-07-23
- 状态：已采用
- 决策：设备中心从能力页面的设备管理入口进入，并在同一功能范围内使用 React 本地状态切换设备总览与单设备详情；静态设备信息集中在独立模拟数据文件中，危险操作与普通操作分别维护本地反馈。
- 原因：设备与家电是能力中心中“设备”能力的细化页面，当前阶段不需要扩展主导航或引入路由；两层视图可以完整表达列表、详情与返回关系，同时保持手机端固定框架和纯前端边界。
- 影响：刷新、返回能力中心或切换主导航后，操作、权限和展开状态都会重置；所有“连接”“停止”“撤权”和自动化操作均不产生网络请求或真实设备副作用，后续接入设备能力时应在展示组件之外增加品牌无关的设备数据与命令层。

## ADR-013｜我的页面采用统一设置分组与瞬时偏好状态

- 日期：2026-07-23
- 状态：已采用
- 决策：账号、智能体、外观、数据、安全和隐私使用统一设置分组承载标题与层级，各专用组件维护自身的瞬时偏好状态，静态资料集中在独立模拟数据文件中；危险数据操作只显示明确的本地反馈。
- 原因：六类设置字段不同但交互层级相近，统一分组有助于手机端快速扫描，并让普通偏好、管理入口和危险数据操作保持清晰边界；本阶段不需要路由、持久化或外部账户能力。
- 影响：刷新或离开页面后主题、背景、气泡、询问方式与开关状态都会重置；账号绑定、数据导出、备份、删除和权限管理均不产生真实副作用，未来接入设置存储时应在展示组件之外增加统一设置数据与命令层。

## ADR-014｜生活月历采用日期键索引与工作台下级本地视图

- 日期：2026-07-23
- 状态：已采用
- 决策：月历从工作台快捷入口进入，在工作台功能范围内使用 React 本地状态切换；事件以 `YYYY-MM-DD` 日期键集中索引，月份网格、日期详情与新增记录共享同一份页面内事件状态。
- 原因：月历需要让月份切换、标记、详情和新增记录保持同步，但当前阶段不需要路由、系统日历或外部数据；日期键索引可以用简单、确定性的结构支持同一天多种事件与即时 UI 更新。
- 影响：刷新、返回工作台或切换主导航后，新增记录与选择状态都会重置；月份切换只查看固定模拟快照，AI 和提醒入口不会发起调用，未来接入真实生活数据时应在组件之外增加日期数据、隐私控制与命令层。

## ADR-015｜管账页将财务展示与资金能力严格分离

- 日期：2026-07-23
- 状态：已采用
- 决策：管账页只渲染集中维护的财务模拟快照，财务总览、账单与分类统计均为只读展示；钱包、自动规则、安全设置和 AI 分析使用统一的无副作用本地反馈，并在页面顶部与安全卡中重复声明无资金操作边界。
- 原因：财务展示能够独立验证信息结构和手机端体验，但钱包、银行、支付与自动扣款属于高风险能力；当前阶段需要从组件和文案两方面避免用户误以为页面可以操作真实资金。
- 影响：页面不会读取账户、连接银行、发起支付、转账或自动扣款，刷新或离开页面后交互提示重置；未来如评估真实财务能力，必须在展示层之外增加独立的安全授权、确认、审计与资金命令层。

## ADR-016｜体重/三围页采用本地记录序列并明确非医疗边界

- 日期：2026-07-24
- 状态：已采用
- 决策：体重/三围页作为工作台下级本地视图，使用类型化模拟记录序列统一驱动当前状态、趋势曲线和日期记录；添加表单只向页面内序列追加模拟记录，AI 入口只显示固定本地反馈，并在页头、说明卡与 AI 区域重复标明非医疗属性。
- 原因：同一份记录需要同步更新数值快照、曲线与列表，本地序列可以在不引入接口、数据库或持久化的前提下完整演示交互；身体数据容易被误解为医疗信息，因此必须把“个人记录”与“医疗诊断”在结构和文案上明确分开。
- 影响：刷新、返回工作台或切换主导航后新增记录会重置，页面不会上传身体数据、调用 AI、生成诊断或输出健康结论；未来如接入真实记录能力，应在展示层之外增加独立的数据授权、隐私保护、持久化与专业健康边界审核。

## ADR-017｜平台后端采用独立工程设计目录与两级记录

- 日期：2026-07-25
- 状态：已采用
- 决策：平台后端统一建立在仓库顶层 `backend/`，与前端根目录 `src/` 和前端工程配置隔离；第一阶段只建立工程设计骨架，不初始化运行时、数据库、API 或模型。后端局部技术决策和详细开发记录分别保存在 `backend/docs/ADR.md` 与 `backend/docs/开发日志.md`，影响平台总体边界的决定及项目级摘要继续同步到 `docs/`。
- 原因：后端后续会拥有独立依赖、配置、测试和发布周期，需要避免与已完成前端混合；同时需要保留项目级单一时间线，并让后端实施细节能够在自身工程内被追踪。
- 影响：后端技术栈、数据库、认证、API、密钥、部署和测试方案必须先形成后端 ADR；平台边界变化仍需更新本文件。第一阶段不得修改前端 `src/`，也不得连接真实外部服务。

## ADR-018｜核心数据模型先固定逻辑归属与版本关系

- 日期：2026-07-25
- 状态：已采用
- 决策：在选择数据库产品和物理结构前，先固定核心对象的用户/主体归属、来源、关系、可见范围、生命周期和版本关系。数据按用户数据、AI 主体数据和平台数据标记并允许叠加；主体状态、消息版本和软件事件保留可追溯历史。
- 原因：这些是 Vio Live 的稳定产品与安全约束，不能依赖某个数据库、ORM 或模型供应商；覆盖式保存也无法支持主体连续性、消息分支、删除、重置、导出和审计。
- 影响：后续物理数据库必须实现跨用户和跨主体隔离、当前版本唯一、来源追溯及用户数据权利；本阶段文档不能直接作为迁移脚本，数据库产品、加密、索引、并发和保留策略仍需单独 ADR。

## ADR-019｜首次前后端连接保持 API 层与页面 mock 分离

- 日期：2026-07-27
- 状态：已采用；替代 ADR-002 的“全项目不连接后端”阶段边界，不改变 ADR-004 等页面本地状态决定
- 决策：前端在 `src/api/` 建立独立 typed 客户端，通过 Vite 同源代理访问平台后端，并只在应用入口进行一次非阻塞健康握手；现有页面、组件和 mock 数据源本阶段不替换。User、Subject 和 Dashboard 数据契约由后端定义，不能从前端 mock 反向推导。
- 原因：本阶段需要验证真实通信基础，同时明确禁止修改页面逻辑或删除 mock。将传输层与展示层分开，可以先稳定错误、超时、返回和归属边界，再在后续明确任务中逐页迁移数据源。
- 影响：应用启动会产生真实 `/health` 请求，但登录、首次设置和工作台仍是本地原型，不能宣称真实账号或真实工作台已经完成。开发期代理不要求后端开放通配 CORS；真实认证和页面数据迁移需要后续独立决策。

## ADR-020｜对话基础拆分稳定消息与不可变版本

- 日期：2026-07-28
- 状态：已采用
- 决策：Conversation 绑定唯一用户与主体；Message 作为时间线上的稳定逻辑记录保存发送者、顺序和当前版本指针；MessageVersion 保存不可覆盖的文本快照、单调版本号和同消息父版本关系。当前阶段只实现线性对话、用户编辑和主体回复重生成记录，不实现分支、删除、重置、上下文装配或模型调用。
- 原因：如果直接覆盖消息正文，就无法同时满足编辑、重生成、历史查询和事件追溯；如果只保存 MessageVersion 而没有稳定 Message，也难以可靠表达时间线位置、发送者和当前版本。将二者拆分可以保持正文单一事实来源，并为后续受控扩展保留边界。
- 影响：编辑和重生成必须匹配当前 `baseVersionId`，旧版本保持不变；主体消息内容由开发调用方显式提交，不得宣称来自 AI。版本、当前指针、会话活动时间和最小 Event 同事务提交；前端对话 mock、本地交互和连续性系统不受本阶段影响。

## ADR-021｜跨窗口连续基础使用可追溯摘要、状态版本与只读上下文投影

- 日期：2026-07-28
- 状态：已采用
- 决策：ConversationSummary 必须保存同用户、主体和会话范围内的 MessageVersion 或同主体 Event 来源，按会话不可变追加；跨窗口读取排除当前 Conversation，只返回同一主体其他窗口的最新摘要。`state_update` 作为带来源的不可变 SubjectState 版本保存，通过独立当前指针读取，不覆盖历史。平台 Context 接口只按“系统安全位置、主体全局设定、当前状态、未解决事件、近期消息、跨窗口摘要、长期记忆位置、本轮用户消息”顺序投影已有数据，不生成提示词、不调用模型或 continuity-engine。
- 原因：跨窗口连续需要在避免全量加载历史的同时保持结论可追溯；摘要和状态若由后端静默推演，会混淆平台持久化与连续性算法边界。只读投影允许未来模型或 continuity-engine 使用稳定数据契约，又不会提前产生 Token、外部请求或虚假能力。
- 影响：当前摘要和状态内容都由开发调用方显式提交；Memory、相关性检索、真实摘要生成、状态演化、Token 预算、分支、删除和窗口重置尚未实现。前端 `src` 与 mock 不变，Dashboard 仍不能宣称 continuity-engine 已可用，当前未认证接口不得公开部署。

## ADR-022｜助手长期全局设定不与动态主体状态混存

- 日期：2026-07-28
- 状态：已采用
- 决策：AI 助手名称与头像继续属于稳定 Subject 身份；人格描述、表达方式、关系定义、长期要求和禁止事项使用 Subject 一对一的 Global Settings 扩展保存。API 与 Context 将两者组合为完整长期设定。Global Settings 是用户明确配置且可更新的长期偏好，SubjectState 是带来源、不可变追加的动态状态快照，两者不互相写入。
- 原因：长期身份和行为约束跨窗口保持，但情绪、强度、未解决事件等状态会随事件演化。混存会让普通设定更新错误覆盖状态历史，也会使模型或连续性结果静默改变用户明确设定。复用 Subject 身份字段并分离扩展设定，可以避免身份双写，又保持清晰的数据所有权。
- 影响：新建主体与默认全局设定原子提交；设定实际变化与最小 `subject_updated` Event 原子提交。设定中的长期要求和禁止事项不得绕过权限、安全或法律约束。当前只提供本地保存、读取、更新和 Context 投影，不生成设定、不调用模型或外部 API；前端 `src` 与 mock 保持不变。

## ADR-023｜模型目录、显式路由规则与真实执行保持分层

- 日期：2026-07-28
- 状态：已采用，仅限平台后端模型与 API 路由基础
- 决策：平台将用户范围的 APIProvider、Provider 下的 Model、按任务唯一的默认/备用 Model Routing Rule，以及只返回本地选择结果的 Router 分为四层。六类任务为聊天、长文本、图片、视频、语音和搜索；显式启用规则不可用时明确失败，规则不存在或停用时才使用稳定目录回退。模型选择不读取或改写 Context、SubjectState 或 Assistant Global Settings，也不意味着供应商、模型或连续性引擎已运行。
- 原因：模型配置与主体连续状态属于不同事实域；若用目录顺序冒充用户默认选择，或让选择动作顺便连接外部服务，会导致配置意图不清、产生未授权费用与数据外传，并可能错误改变主体状态。
- 影响：Provider 保存 Base URL 和接口格式，Model 保存能力与费用说明；测试状态当前只保留 `not_tested`，真实连通性、计费和故障切换未实现。API Key 仅有拒绝写入的安全存储接口，仓库、SQLite、普通响应和日志均不保存真实密钥。前端 `src`、MCP、Tool、平台后端 7 及真实模型接入不在本阶段范围。

## ADR-024｜能力注册、主体权限视图与真实执行严格分离

- 日期：2026-07-28
- 状态：已采用，仅限 MCP、Skill、插件与 Tool 基础系统
- 决策：平台分别保存 Tool、MCP、Skill 和 Plugin 注册元数据，并按主体统一投影分类、注册状态、Permission 结果和 Tool 最近使用记录。Tool、MCP 与 Skill 复用现有精确 Permission 资源；Plugin 当前只登记信息，不安装、不加载，也不扩张 Permission。Tool 使用入口只执行 Permission → Security → Confirmation 的准备判断并保存固定 `not_executed` 记录，不接受或执行真实 Tool 参数。
- 原因：能力目录是平台配置事实，真实连接、安装和执行是高风险副作用，两者必须能被独立验证和授权。如果把 `enabled` 当成已连接或可执行，会绕过安全确认并制造虚假的外部能力状态。
- 影响：MCP 始终标记未连接，Plugin 始终标记未安装，Skill/Tool 始终标记执行器未实现；“准备完成”也不等于已经执行。未来接入真实 MCP、插件或 Tool 必须新增受信适配器、供应链与秘密治理、超时/幂等/撤销策略和独立 ADR。当前不修改前端 `src`，不访问设备、第三方服务、真实模型或 continuity-engine。

## ADR-025｜设备登记、能力授权与真实设备控制分层

- 日期：2026-07-28
- 状态：已采用，仅限手机、家电与穿戴设备适配基础
- 决策：平台使用统一 Device Registry 表达七类设备和四种能力，使用未配置 Adapter 契约表达未来 Xiaomi、Midea、Apple、Android 接入；主体使用设备能力前必须经过精确 Device Permission、Security 和 Confirmation。当前只保存注册、授权、操作请求 Event 和固定未执行日志，不保存厂商凭据、设备状态或控制参数，也不调用任何真实设备。
- 原因：前端设备展示、平台注册、权限确认和真实控制不能合并为一个“连接”开关。将真实副作用隔离在尚未实现的厂商 Adapter 之外，可防止模拟状态被误认成已连接，并为摄像头、穿戴和家电等高风险资源保留统一安全门槛。
- 影响：设备启用仍固定未连接，操作确认通过仍固定未执行；所有设备操作按极高风险每次确认。未来接入任何品牌前必须独立审查设备身份、厂商认证、秘密存储、健康/位置/影像数据、撤销、立即停止、超时、重试、幂等和审计策略。当前前端 `src`、手机权限、家电控制、摄像头调用、厂商 API、模型和 continuity-engine 均不变。

## ADR-026｜自定义安全栏只能收紧权限并保留平台风险底线

- 日期：2026-07-28
- 状态：已采用，仅限权限与自定义安全栏
- 决策：Vio Live 将 Permission、用户 Security Policy 和具体 Confirmation 作为依次收紧的三层。用户可配置默认风险、高风险策略、自动确认范围、禁止范围及精确资源/动作/风险规则，但不能放宽 Permission 拒绝；高风险和极高风险始终逐次确认。`session_allow` 只在明确确认后生成精确作用域、短时、策略版本绑定的开发期授权，客户端安全会话 ID 不承担认证。
- 原因：用户需要能表达自己的安全边界，但偏好配置不能替代基础授权或平台不可降级规则。把配置、具体确认和未来执行拆分，可避免“允许”被误解为真实操作已经发生，并防止旧确认在策略变化后重放。
- 影响：安全检查固定为 Permission → Policy → Confirmation → 未执行准备；策略、偏好、确认请求和最终结果进入最小审计，Permission 生命周期和确认请求进入 Event。真实账号会话、Tool/设备执行、外部服务、手机权限和 AI 私域仍未开发；前端 `src` 不变。

## ADR-027｜AI 私域与 User Space 分库存储并通过独立安全门读取

- 日期：2026-07-28
- 状态：已采用
- 决策：AI Private Space 使用专用 Space 与不可变内容版本表，按用户与助手复合归属隔离，不与普通 User Space 混存。创建空 Space 只用于生成精确授权目标，不接收正文；其后读取、写入、状态、Context 投影与导出准备必须经过 `private_domain` Permission → Security Policy → Confirmation。通用 Conversation Context 不自动包含私域，Event/AuditLog 不复制正文，导出当前只预留不含正文的版本清单。
- 原因：AI 私域属于高敏感主体数据，独立存储和显式安全入口能减少误查询、通用装配与日志复制导致的泄露。不可变版本保留来源和未来迁移所需关系；引导创建空容器可解决资源 ID 与精确 Permission 的先后依赖。
- 影响：当前只保存调用方明确提交的五类私域记录，不实现真实意识、自主行为、披露判断、删除、文件导出、模型/continuity-engine 生成或机器人连接。后续任何真实生成、开放、迁移和生产加密都需独立安全与产品决策。

## ADR-028｜生活数据属于 User Space 并使用独立高敏感访问边界

- 日期：2026-07-28
- 状态：已采用
- 决策：管账、月历、身体管理和本地记忆属于 User Space，不与 AI Private Space 混存。所有记录同时绑定用户和主体，通过 `life_data` Permission → Security Policy → Confirmation 访问；财务和身体统计只对已保存的显式数据作本地确定性计算。生活 Event 不复制金额、健康数值、亲密内容、备注或记忆正文。
- 原因：生活数据虽可供助手在明确授权后使用，但所有权、导出与上下文选择权仍属于用户。独立存储和安全资源类型能避免将生活隐私错误视为 AI 私域或普通非敏感记忆，也避免页面浏览自动触发模型或外部同步。
- 影响：当前不连接支付、银行、穿戴设备、医疗服务、外部 API 或模型。AI 建议只保存调用方显式内容，身体趋势不构成诊断；本地记忆只有显式标记后才会出现在独立 Context 投影。真实提醒执行、同步、删除和导出需后续决策。

## ADR-029｜用户空间只保存当前助手指针，数据访问先验证复合归属

- 日期：2026-07-28
- 状态：已采用，仅限平台后端账号与数据隔离基础
- 决策：每个 User 建立唯一 User Space，保存开发期身份状态、空间状态和可空当前助手指针。当前助手必须属于同一用户，切换只更新空间指针；Assistant Global Settings、Assistant Private Space、SubjectState、对话、事件和生活数据继续独立保存。平台统一数据访问边界必须先用预定义的用户/助手/资源复合查询验证所有权，所有权成立后，私域、设备和生活资源仍依次经过 Permission、Security Policy 与 Confirmation。
- 原因：当前助手属于用户侧选择而不是 AI 动态状态；把它写进 Subject 会混淆身份与导航偏好。所有权校验也不能被 Permission 替代，先以全局资源 ID 读取再比较用户容易产生遗漏和存在性泄露。固定复合查询与安全链分层可以同时保证多空间隔离和高敏感访问控制。
- 影响：新增开发 SQLite `user_spaces`、助手切换与五类数据边界检查。开发身份固定标记未认证，URL、`x-vio-user-id` 和安全会话 ID 都不是登录凭证；所有访问检查均不执行资源。真实登录、第三方账号、生产行级安全、租户分区、语音和外部服务不在本阶段范围，前端 `src` 不变。
