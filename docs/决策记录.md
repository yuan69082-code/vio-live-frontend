# Vio Live 决策记录

## ADR-001｜前端技术栈

- 日期：2026-07-22
- 状态：已采用
- 决策：使用 React + Vite + TypeScript 建立 Vio Live 前端项目。
- 原因：项目需要组件化页面结构、快速本地开发体验与明确的类型检查能力。

## ADR-002｜当前开发边界

- 日期：2026-07-22
- 状态：已采用
- 决策：当前阶段只开发前端页面，不连接后端、数据库或 API。
- 影响：登录页中的 Google 登录、邮箱验证码和登录/注册均只提供前端原型与本地演示反馈，不执行真实身份验证。

## ADR-003｜页面开发顺序

- 日期：2026-07-22
- 状态：已采用
- 决策：按规划逐页开发并逐页审查，不提前开发后续页面。
- 当前结果：登录页原型已完成。
- 下一项：首次设置页面。

## ADR-004｜首次设置原型的页面流与状态

- 日期：2026-07-22
- 状态：已采用
- 决策：登录页与首次设置页暂时使用 React 本地状态完成页面切换，不引入路由、持久化或外部服务。
- 原因：当前阶段只验证单用户首次设置体验，保持原型简单，并严格遵守不连接后端、数据库或 API 的开发边界。
- 影响：刷新页面会回到登录页，首次设置内容不会保存；待后续整体导航与数据方案确定后再调整。

## ADR-005｜主导航采用配置驱动的本地状态切换

- 日期：2026-07-22
- 状态：已采用
- 决策：六个主导航入口由统一配置数组生成，当前使用 React 本地状态切换占位页，不引入路由库。
- 原因：本阶段只建立手机端导航骨架，统一配置可以保证入口顺序、标签、图标和占位页保持一致，同时避免提前引入具体页面架构。
- 影响：导航切换不会产生真实 URL 或持久化状态；待具体页面与整体路由需求明确后再评估路由方案。

## ADR-006｜工作台采用展示组件与集中模拟数据

- 日期：2026-07-22
- 状态：已采用
- 决策：工作台页面拆分为关注卡片、今日概览、最近变化、快捷入口、通用输入框和共用图标组件；模拟内容集中放在独立数据文件中。
- 原因：页面模块较多，展示组件与数据分离可以保持第一屏清晰，也便于后续在不改变视觉组件的情况下替换真实数据来源。
- 影响：当前组件只消费本地模拟数据，不承担数据请求、持久化或业务执行。

## ADR-007｜工作台使用固定视口与内部滚动

- 日期：2026-07-22
- 状态：已采用
- 决策：主导航外框固定为当前视口高度，工作台顶部、通用输入框和底部导航保持固定，只有工作台主体内容独立滚动。
- 原因：手机端需要让通用输入和主导航随时可用，同时避免从较长的首次设置页进入后继承外层滚动位置。
- 影响：后续主导航页面需要明确自身内容滚动区域，不能依赖整个文档页面滚动。

## ADR-008｜对话页采用固定控制区与独立消息滚动

- 日期：2026-07-23
- 状态：已采用
- 决策：对话页顶部、模型与上下文控制、记忆/状态/工具入口及输入区保持固定，只有消息列表独立滚动；页面按展示职责拆分组件，并集中维护模拟数据。
- 原因：手机端长对话需要让会话信息、上下文状态、输入工具与主导航随时可用，同时避免页面级滚动造成输入区位置不稳定。
- 影响：当前各控件只提供本地界面状态，消息操作与发送不执行真实逻辑；后续接入真实能力时，应在不改变展示组件职责的前提下增加数据与命令层。

## ADR-009｜连续性信息采用类型化卡片与集中模拟快照

- 日期：2026-07-23
- 状态：已采用
- 决策：连续性页面将身份、关系、近期延续、时间节点和形成中的想法组织为统一类型的展示卡片，当前状态使用专用卡片；全部模拟内容集中在独立数据文件中，页面主体独立滚动。
- 原因：连续性信息类别多但展示结构稳定，统一数据结构可以降低重复组件数量，并让特殊状态视觉与普通信息卡片保持清晰边界。
- 影响：当前页面只渲染一次本地模拟快照，不进行真实记忆读取、写入、推断或状态持久化；未来接入数据层时应保持展示组件不直接依赖外部服务。

## ADR-010｜AI 私域申请采用确定性本地状态机

- 日期：2026-07-23
- 状态：已采用
- 决策：AI 私域目录与申请页使用 React 本地状态切换；每个模拟目录项目预设一种回复状态，由统一状态映射决定开放范围与展示文案。
- 原因：本阶段需要完整演示全部开放、部分开放、暂时拒绝和延后开放四种结果，同时必须避免产生任何真实 AI 判断、网络请求或持久化行为。
- 影响：同一目录项目每次都会返回固定模拟结果，返回目录后申请理由和回复状态会重置；未来接入真实审批能力时，应将判断与记录逻辑放在独立数据层，展示组件只消费明确结果。

## ADR-011｜能力中心采用统一分组壳与局部模拟状态

- 日期：2026-07-23
- 状态：已采用
- 决策：模型/API、MCP、Skill、插件、Tool 和设备使用统一能力分组壳承载标题、图标与状态摘要，各专用组件只管理自身的本地交互状态，静态能力信息集中在独立模拟数据文件中。
- 原因：六类能力展示字段不同，但层级和视觉结构一致；统一分组可以减少重复布局，同时让启停、连接测试和管理反馈保持在对应能力范围内。
- 影响：刷新或离开页面后所有模拟交互会重置，任何按钮和开关都不会产生网络、安装、授权、卸载或设备控制副作用；未来接入真实服务时，应在组件之外增加统一能力数据与命令层。

## ADR-012｜设备中心采用能力入口下的两层本地视图

- 日期：2026-07-23
- 状态：已采用
- 决策：设备中心从能力页面的设备管理入口进入，并在同一功能范围内使用 React 本地状态切换设备总览与单设备详情；静态设备信息集中在独立模拟数据文件中，危险操作与普通操作分别维护本地反馈。
- 原因：设备与家电是能力中心中“设备”能力的细化页面，当前阶段不需要扩展主导航或引入路由；两层视图可以完整表达列表、详情与返回关系，同时保持手机端固定框架和纯前端边界。
- 影响：刷新、返回能力中心或切换主导航后，操作、权限和展开状态都会重置；所有“连接”“停止”“撤权”和自动化操作均不产生网络请求或真实设备副作用，后续接入设备能力时应在展示组件之外增加品牌无关的设备数据与命令层。

## ADR-013｜我的页面采用统一设置分组与瞬时偏好状态

- 日期：2026-07-23
- 状态：已采用
- 决策：账号、智能体、外观、数据、安全和隐私使用统一设置分组承载标题与层级，各专用组件维护自身的瞬时偏好状态，静态资料集中在独立模拟数据文件中；危险数据操作只显示明确的本地反馈。
- 原因：六类设置字段不同但交互层级相近，统一分组有助于手机端快速扫描，并让普通偏好、管理入口和危险数据操作保持清晰边界；本阶段不需要路由、持久化或外部账户能力。
- 影响：刷新或离开页面后主题、背景、气泡、询问方式与开关状态都会重置；账号绑定、数据导出、备份、删除和权限管理均不产生真实副作用，未来接入设置存储时应在展示组件之外增加统一设置数据与命令层。

## ADR-014｜生活月历采用日期键索引与工作台下级本地视图

- 日期：2026-07-23
- 状态：已采用
- 决策：月历从工作台快捷入口进入，在工作台功能范围内使用 React 本地状态切换；事件以 `YYYY-MM-DD` 日期键集中索引，月份网格、日期详情与新增记录共享同一份页面内事件状态。
- 原因：月历需要让月份切换、标记、详情和新增记录保持同步，但当前阶段不需要路由、系统日历或外部数据；日期键索引可以用简单、确定性的结构支持同一天多种事件与即时 UI 更新。
- 影响：刷新、返回工作台或切换主导航后，新增记录与选择状态都会重置；月份切换只查看固定模拟快照，AI 和提醒入口不会发起调用，未来接入真实生活数据时应在组件之外增加日期数据、隐私控制与命令层。

## ADR-015｜管账页将财务展示与资金能力严格分离

- 日期：2026-07-23
- 状态：已采用
- 决策：管账页只渲染集中维护的财务模拟快照，财务总览、账单与分类统计均为只读展示；钱包、自动规则、安全设置和 AI 分析使用统一的无副作用本地反馈，并在页面顶部与安全卡中重复声明无资金操作边界。
- 原因：财务展示能够独立验证信息结构和手机端体验，但钱包、银行、支付与自动扣款属于高风险能力；当前阶段需要从组件和文案两方面避免用户误以为页面可以操作真实资金。
- 影响：页面不会读取账户、连接银行、发起支付、转账或自动扣款，刷新或离开页面后交互提示重置；未来如评估真实财务能力，必须在展示层之外增加独立的安全授权、确认、审计与资金命令层。

## ADR-016｜体重/三围页采用本地记录序列并明确非医疗边界

- 日期：2026-07-24
- 状态：已采用
- 决策：体重/三围页作为工作台下级本地视图，使用类型化模拟记录序列统一驱动当前状态、趋势曲线和日期记录；添加表单只向页面内序列追加模拟记录，AI 入口只显示固定本地反馈，并在页头、说明卡与 AI 区域重复标明非医疗属性。
- 原因：同一份记录需要同步更新数值快照、曲线与列表，本地序列可以在不引入接口、数据库或持久化的前提下完整演示交互；身体数据容易被误解为医疗信息，因此必须把“个人记录”与“医疗诊断”在结构和文案上明确分开。
- 影响：刷新、返回工作台或切换主导航后新增记录会重置，页面不会上传身体数据、调用 AI、生成诊断或输出健康结论；未来如接入真实记录能力，应在展示层之外增加独立的数据授权、隐私保护、持久化与专业健康边界审核。

## ADR-017｜平台后端采用独立工程设计目录与两级记录

- 日期：2026-07-25
- 状态：已采用
- 决策：平台后端统一建立在仓库顶层 `backend/`，与前端根目录 `src/` 和前端工程配置隔离；第一阶段只建立工程设计骨架，不初始化运行时、数据库、API 或模型。后端局部技术决策和详细开发记录分别保存在 `backend/docs/ADR.md` 与 `backend/docs/开发日志.md`，影响平台总体边界的决定及项目级摘要继续同步到 `docs/`。
- 原因：后端后续会拥有独立依赖、配置、测试和发布周期，需要避免与已完成前端混合；同时需要保留项目级单一时间线，并让后端实施细节能够在自身工程内被追踪。
- 影响：后端技术栈、数据库、认证、API、密钥、部署和测试方案必须先形成后端 ADR；平台边界变化仍需更新本文件。第一阶段不得修改前端 `src/`，也不得连接真实外部服务。

## ADR-018｜核心数据模型先固定逻辑归属与版本关系

- 日期：2026-07-25
- 状态：已采用
- 决策：在选择数据库产品和物理结构前，先固定核心对象的用户/主体归属、来源、关系、可见范围、生命周期和版本关系。数据按用户数据、AI 主体数据和平台数据标记并允许叠加；主体状态、消息版本和软件事件保留可追溯历史。
- 原因：这些是 Vio Live 的稳定产品与安全约束，不能依赖某个数据库、ORM 或模型供应商；覆盖式保存也无法支持主体连续性、消息分支、删除、重置、导出和审计。
- 影响：后续物理数据库必须实现跨用户和跨主体隔离、当前版本唯一、来源追溯及用户数据权利；本阶段文档不能直接作为迁移脚本，数据库产品、加密、索引、并发和保留策略仍需单独 ADR。
