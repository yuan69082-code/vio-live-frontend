## 页面接线

- 六个主导航保持不变；“连续性”导航内新增当前助手的真实本地长期记忆中心。
- 旧连续性卡片保留，但明确标为非 R5 模拟原型，不与真实记忆混合。
- 当前用户来自 R2 已验证个人会话，当前助手来自服务端选择；请求路径、查询和正文不传 `userId`、`assistantId` 或 `subjectId`。
- 已接页面动作：列表/确定性关键词搜索/筛选/游标下一页、详情、新建、完整替换编辑、上下文纳入开关、归档/恢复、不可变版本、来源引用、删除申请/撤销/最终删除及删除凭据查询、严格 JSON 导入、受控导出下载、原幂等键恢复。
- 读取与写入均展示加载、空态、失败、未知结果、确认等待和重试；敏感 GET 只通过 `X-Vio-Confirmation-Id` / `X-Vio-Security-Session-Id` 头恢复读取，不把确认信息放入 URL。
- 写操作防重复点击；确认往返复用原正文与原幂等键。网络中断、超时或响应无法验证时保留原键并只允许查询，不换键盲目重发。
- 助手、身份或页面上下文变化会终止旧观察并清除对应恢复索引；迟到成功、失败和 `finally` 不更新新视图。

## 浏览器数据边界

- 记忆正文、摘要、导入正文、导出文档和完整响应不写入 `localStorage` 或 `sessionStorage`。
- 页面只允许暂存操作类型、幂等键及必要的不透明资源 ID；完成、退出、身份变化或助手变化后按作用域清理。
- 导出文件仅由已授权 HTTP 响应构造临时 `Blob` 并立即撤销对象 URL；服务端不接收文件路径。
- R5 不调用 Provider、真实 Engine、外部运行时或业务互联网，不创建自动模型记忆。

## 真实本地浏览器证据

- 环境：受控临时个人身份、隔离 SQLite、两个助手和 loopback Provider；浏览器经 Vite 代理访问真实本地 HTTP。控制面最终持续报告 `engine=not_accessed`、`externalProvider=not_used`、`providerCharge=not_incurred`。
- 创建与版本：真实创建两条记忆，关闭上下文资格后分别形成 v2；服务端保持 2 条记忆、4 个不可变版本。页面只在明确读取后显示正文和来源。
- 助手/所有者隔离：切换第二助手时列表为 0，切回第一助手恢复原列表；使用另一受控所有者登录时看不到第一所有者正文，切回后数据恢复。未向请求传测试身份头或正文归属参数。
- R4 装配：一条 `includeInContext=true` 记忆被真实上下文计划选中，锁定轮次的 `memory_slot` 展示 1 条精确证据、版本 ID、MemoryVersion 内容哈希和 ContextSource 载荷哈希；同一轮经安全确认后由 loopback Provider 完成，控制面仅 1 次 Provider 调用。随后关闭全部记忆资格，计划真实显示“长期记忆 无内容 · 0/0”，消息输入仍可用。
- 响应丢失恢复：后端仅丢弃一次 R5 创建响应；页面显示结果未知并只提供“按原操作键查询”，使用原幂等键查询、确认和完成后总记忆数为 2，没有盲目换键或重复事实。控制面记录 `droppedResponses=1`。
- 生命周期：归档后用显式 `status=archived` 筛选得到且仅得到目标记录，随后恢复；默认列表恢复为两条 `active` 记录。删除申请、等待态、撤销、测试时钟到期及最小删除凭据展示已在前一受控夹具完成，失败/未完成状态不会显示整体完成。
