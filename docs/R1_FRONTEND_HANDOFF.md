# R1 前端交接：个人独立聊天

状态：前端实现、自动化和受控真实本机页面闭环已完成；总体协调窗口于 2026-09-05 正式验收 R1 通过。本文只记录 R1 前端，不代表 R3、外部运行时、真实供应商、手机实机、云同步或部署完成。

## 接口与身份来源

前端严格以 `backend/docs/R1_STANDALONE_CHAT_CONTRACT.md` 为唯一 R1 接口来源，复用 R2 的 `vio_personal_session` Cookie、CSRF 和服务端当前助手。个人主入口不会读取或发送固定用户、固定助手、固定会话、`x-vio-user-id` 或旧 `LOCAL_CONVERSATION_PROFILE`。

| 页面动作 | 真实接口 | 成功结果 | 失败或结果未知后的恢复 |
| --- | --- | --- | --- |
| 打开六导航“对话” | `GET /api/v1/personal/chat/default` | 显示当前助手名称、头像、唯一默认会话和服务端消息版本 | 明示失败；只读重试，不创建会话 |
| 发送消息 | `POST /api/v1/personal/chat/turns` | 只合并服务端返回的用户消息、轮次和助手消息 | 网络、超时或响应不可验证时保留原随机键，先按键查询 |
| 查询未知提交 | `GET /api/v1/personal/chat/turns/by-idempotency-key/{key}` | 恢复已持久化轮次 | 只有服务端明确 `404` 才开放沿用同一键安全重试 |
| 查询处理中轮次 | `GET /api/v1/personal/chat/turns/{turnId}` | 更新真实轮次和消息 | 查询失败不触发 Provider，也不伪造完成 |
| 批准等待确认 | R2 confirmation decision + `POST .../{turnId}/recovery` | 继续同一轮次 | 结果未知时保留恢复键；先查 turnId，再按原键恢复 |
| 安全重试 | `POST .../{turnId}/recovery`，`action=retry` | 仅对后端明确 `retryable` 的同一轮次执行 | `outcome_unknown` 不提供重试 |
| 终止轮次 | `POST .../{turnId}/recovery`，`action=cancel` | 显示服务端终止事实 | 失败明确显示“终止失败”，保留原恢复键核对 |
| 配置问题跳转 | 主导航内部真实切换 | 进入“能力”；无助手进入“我的” | 不显示无效配置按钮 |

所有写请求由既有个人 API 层附加同源 CSRF；聊天写请求各携带一个 `Idempotency-Key`。浏览器恢复区只保存随机键以及必要的 `turnId`、助手索引和恢复动作索引，不保存消息正文、口令、密钥、完整响应或 Provider 内容。退出、身份变化和页面卸载会终止旧请求观察；退出或身份变化会清理对应用户的 R1 恢复索引。

## 页面行为

- 登录后的六导航保持不变，“对话”现在挂载 `PersonalConversationPage`；历史固定 Profile 页面只保留为非个人入口和历史测试证据。
- 每个助手只展示一个服务端默认会话；没有会话时只显示空态，不通过读取动作创建会话。
- 输入提交后立即锁定重复发送并显示处理中；在后端返回之前不插入用户气泡或助手气泡。
- 助手变化会卸载旧页面、取消旧请求并按新助手重新读取；请求代次同时阻止迟到成功、失败和 `finally` 修改新视图。切回助手时重新读取该助手服务端历史。
- 页面区分未选择助手、配置缺失/停用、Vault 未解锁、凭据不可用、普通失败、结果未知、安全重试和终止失败。
- 手机样式延续现有对话布局；状态操作在 420px 以下改为纵向排列，消息正文允许安全换行，避免长内容造成横向溢出。

## 前端文件

- `src/api/personal-chat-api.ts`：R1 精确响应投影、状态校验和个人聊天接口。
- `src/api/personal-chat-recovery.ts`：每用户/每助手的最小随机恢复事实。
- `src/pages/PersonalConversationPage.tsx`：真实历史、发送、查询、恢复、切换隔离和状态展示。
- `src/pages/MainNavigation.tsx`：将个人“对话”入口接到 R1 页面。
- `src/components/conversation/*` 与 `src/styles.css`：复用布局，补充真实助手头像、名称、长度上限和窄屏状态布局。
- `src/state/PersonalContext.tsx`：退出、401 与身份变化时清理当前用户的聊天恢复观察。
- `src/api/personal-chat-*.test.ts`、`src/pages/PersonalConversationPage.test.tsx`、`src/App.test.tsx`：接口、存储、并发恢复和主入口回归。

### 真实本机浏览器

全部页面证据使用新建临时 SQLite、R2 个人服务端会话、两个临时助手、受控 loopback `openai_compatible` Provider 和非真实测试凭据。没有浏览器请求 mock、真实 Provider、业务公网、Engine 或费用。

- 登录后六导航“对话”直接显示当前助手与空的唯一默认会话。第一助手发送后显示真实用户 MessageVersion，经真实安全确认得到 `Controlled assistant response.`；第二助手独立发送并得到同源真实回复。切回第一助手只显示第一助手历史，第二助手正文计数为 0。
- 页面刷新后第一助手历史恢复；退出后业务导航消失并要求重新验证；使用新的个人访问会话重新登录后，原服务端历史继续存在。
- 真实停用 Model 和 Provider 后，聊天分别显示“默认聊天模型已停用”“供应商已停用”及可用的“进入能力配置”；恢复配置后只通过同一轮次的显式安全重试完成。真实锁定 Vault 后显示“凭据库尚未解锁”，在能力页受控解锁后同样恢复原轮次。
- 首次 POST 响应丢失使用一次性本机转发层实现：请求完整进入真实隔离后端，转发层读完后端响应后才断开浏览器连接。页面显示“结果尚未确认”并保留原随机键；点击“按原键查询”通过合同查询恢复同一用户消息和等待确认轮次，没有换键重发。批准后只记录 **1 次** loopback Provider 调用并显示真实回复；页面消息区只出现 1 条该用户消息。
- 390×844 视口下，浏览器测得 document、body 与 `.conversation-page` 的 `clientWidth` 和 `scrollWidth` 全部相等（该环境报告 391 CSS px），无横向溢出；状态按钮在窄屏纵向排列。
- 正常聊天、配置故障恢复和响应丢失恢复完成后，页面控制台均为 **0 error、0 warning**。故意断开响应只产生预期的本机代理传输失败，不进入页面控制台，也不被显示为成功。
- 所有临时后端、Provider、转发层和 Vite 服务均已停止；三个一次性测试数据库根、临时脚本与本轮 `dist/` 均已删除。未留下测试日志或运行数据。
