# Vio Live 后端第一阶段实施路线

## 阶段定位

第一阶段是平台后端的工程设计阶段，目标是把 `docs/后端/` 中的稳定规划转化为可实施的工程边界、决策清单、数据设计任务和验收门槛。

本阶段不交付可运行后端，不连接真实数据库、API、模型、MCP、Tool、设备或第三方服务。

## 阶段目标

1. 明确后端独立目录、模块职责和依赖方向。
2. 建立后端 ADR、开发日志与项目级文档的同步规则。
3. 将用户、主体、会话、事件、权限等核心对象转化为下一阶段可落地的数据设计清单。
4. 明确前端、平台后端、continuity-engine、模型和外部能力之间的契约设计任务。
5. 在初始化运行工程前完成技术栈、安全、测试和部署方案决策。

## 实施批次

### 1A｜范围冻结与工程边界

- 确认第一版必须覆盖与暂缓范围。
- 创建独立 `backend/` 目录。
- 定义 `core`、`modules` 和 `integrations` 的职责及依赖方向。
- 建立后端 README、ADR、开发日志和路线文档。

完成标准：目录可被 Git 追踪；所有说明一致表明当前无可运行后端和外部连接。

### 1B｜技术决策准备

- 评估并决定后端语言、运行时和框架。
- 评估并决定数据库、数据访问和迁移方案。
- 决定认证、会话、API、错误模型和接口版本策略。
- 决定密钥、配置、部署、日志、监控和测试方案。

完成标准：阻塞性选择均有已采用 ADR，不以临时代码代替决策。

### 1C｜领域与数据设计

优先形成下列核心对象的概念模型、归属关系、唯一标识、生命周期和删除规则：

- 用户账号与登录身份
- 智能体主体及用户—主体归属
- 会话、消息、消息版本、分支与重置记录
- 软件事件与来源引用
- 权限、授权、确认、撤销与访问记录
- 摘要、记忆引用和状态交换记录

第二组对象只确认边界和关联，不在本批次同时实现：模型配置、扩展能力、设备、AI 私域、生活模块、导出与备份。

完成标准：每类数据都能回答属于哪个用户和主体、从何产生、谁可读取、如何版本化、如何导出和删除。

### 1D｜契约设计

- 定义前端与平台后端的身份、主体选择和受控数据访问边界。
- 定义软件事件的通用头部、来源、可见范围和版本原则。
- 定义平台后端与 continuity-engine 的请求和响应职责。
- 定义未来模型调用中 `reply` 与 `state_update` 的逻辑边界。
- 定义权限失败、主体不匹配、服务不可用和高风险确认的结果语义。

完成标准：契约不依赖前端模拟数据结构，不暴露数据库结构、密钥或 continuity-engine 内部算法。

### 1E｜安全与测试设计

- 建立跨用户、跨主体和越权访问测试矩阵。
- 建立消息版本、事件脱敏、权限五档、撤销与高风险确认测试矩阵。
- 建立备份恢复、导出删除和敏感字段检查清单。
- 规定真实服务接入前的最小自动化检查。

完成标准：每个核心边界都有可执行的验收场景，公开测试门槛能够被验证。

### 1F｜进入实现前审查

- 审查 ADR 是否完整且相互一致。
- 审查领域模型、接口契约和测试矩阵是否覆盖第一版基础能力。
- 审查前端是否仍只通过未来平台接口访问受控能力。
- 确认没有密钥、用户数据或供应商协议被写入仓库。

完成标准：形成明确的“可以初始化工程”结论，并由新的开发任务授权进入下一阶段。

## 当前完成情况

- 1A 已完成：独立目录、职责边界和文档治理已经建立。
- 1B 已形成待决策清单，具体技术选择尚未作出。
- 1C 至 1F 已明确输入、输出和完成标准，等待后续单独任务逐项落实。

## 下一阶段入口

下一阶段应从阻塞性 ADR 开始，不直接连接真实服务。只有在运行时、数据库、认证、API、密钥、部署和测试方案全部确认后，才能初始化最小后端工程，并优先实现账号、主体归属和隔离测试。

## 明确暂缓

- 真实数据库连接和迁移执行
- 公开 API 与网络服务
- 模型路由和实际 Token 消耗
- continuity-engine 真实调用
- MCP、Tool、插件和设备真实调用
- 生活模块真实数据
- AI 私域真实开放判断
- 真实资金操作和医疗诊断
